# 技能排队：实际判定区间与后续等价状态

2026-09-17，接续 [固定状态优化](skill-queue-fixed-state-optimization.md)。本轮尚未提交。

## 实现

谱面初始化时，用完整调度器和 17 种支持时长生成六层有向无环状态表，再反向按以下签名合并状态：对每个时长，输出的实际判定区间和下一层等价类均相同。只合并当前覆盖音符相同的状态是不安全的，空白间隔中的不同释放时刻仍可能影响后续。

手动使用原来的 60 FPS 整数帧规则；Auto 仍采用原时间包络规则。完整解析后的判定节点（包括技能标记节点）、同一时刻的先后关系、Fever、递增加分的逐音符倍率、基础分和倍率的分别取整均保留。

- 无排队：原独立整数增量矩阵及原有同分种子策略。
- 非连锁：原前驱条件矩阵、相同窗口复用和固定状态分配内核。
- 连锁：按具体五张卡的时长缓存可达的 `已用卡集合 × 等价状态` 图，只对不同的卡牌/判定区间组合计算整数增量，再求最优顺序；第六次可选的卡必须是五卡中的队长。
- 平均 PT：同一状态图提供每个排列的得分，不将不同排列的概率质量当成一条最大值路径。原 96 种可达排列、总权重 1024 不变，最高分概率继续汇总所有同分最优排列。
- 指定队伍：按用户确认的方式保留完整时间线穷举。

## 连锁贡献剪枝

同一支配比较中，替换前后必须选择相同的后续技能。逐步推进两份状态，求所有允许续接方式的连续 Meta 差值下界；普通替换进入相同后续等价类即可停止计算时间差，队长仍需处理第六次的不同技能输入。

设替换后的综合力为 `Sa`，替换前为 `Sb`，连续技能 Meta 总量为 `Ma/Mb`。利用恒等式：

`Sa×Ma − Sb×Mb = Sa×(Ma−Mb) + (Sa−Sb)×Mb`

成对状态 DP 缓存 `Ma−Mb` 的下界；`Mb` 使用包含该卡及队长复唱约束的总 Meta 区间。根据综合力差的符号选择区间端点，再加基础分变化、在队友综合力端点上取最小值，最后扣除保守取整误差。缓存按技能形状共享，避免逐卡对重跑谱面和逐队伍枚举。

该下界允许重复使用其余技能形状、不强制其角色互异，因而是实际合法队伍的超集；可以保守地少剪，不能据此多剪。相同时长、类型且综合力/倍率不差的硬支配保持不变。贡献剪枝没有整体关闭。

普通替换之后的续接只依赖两份状态，不再依赖被替换卡的身份；这些续接下界在所有卡牌比较之间共享。队长续接还需包含第六次重复的技能形状，按形状对缓存。替换前相同的前缀使用预先计算的可达状态集合，相同时长的后续技能先合并其差值下界，再推进同一对后继状态。测试将该共享版本与未共享的成对状态递归逐项比较，要求下界完全相同。

所有依赖技能上界的巡回候选、道具组合、强制卡与剩余队伍上界，改为覆盖连锁状态中的全部可达窗口；逐位置取最大值是乐观上界，不能用于证明支配。

## 正确性验证

- Core/Data/Service 回归：237 项通过，10 项既有可选测试跳过。
- 最终共享缓存版本的 26 项排队相关测试、5 项网页提示测试再次通过；WASM Release 已重新构建。
- 新状态转换随机序列与原调度器逐步比较；最高分和各排列分数比较覆盖手动、Auto、Fever、普通/递增技能、低综合力取整边界、全部队长位置。
- 连锁贡献下界逐一与实际整数分差比较，包括降低综合力、改变时长、队长复唱及中途重新同步。
- 新增连锁三曲的小型无剪枝枚举，对照生产贡献剪枝、道具上界及接近最优的 incumbent 剪枝，最优三队一致。
- 3,431 张离线谱面中的 559 组非连锁、59 组连锁配置，对照 370,800 个完整时间线排列/队长组合。786 SPECIAL 的异常技能点数量单独排除，不计入覆盖。

覆盖全部 17 种时长（包含 8 秒）时，186/761 HARD 手动原始进入状态数为 `1/17/17/17/82/89`，最小化后为 `1/1/1/15/23/19`；Auto 原始为 `1/17/17/17/102/144`，最小化后相同。127 EXPERT 手动由 `1/17/40/69/17/17` 变为 `1/3/6/1/1/1`。实际五卡队伍只访问其中的子图。

## 基准口径

使用冻结的 1,456 卡国服活动 323 档案。原生 Windows Rust Release，最高分强制精确搜索，平均 PT 使用完整分带搜索，关闭额外全局剪枝诊断，编译和测试不与计时并行。

对照二进制为上一轮 `tmp/queue-second-optimization/optimized.exe`。原三曲无排队输入、8 SP 单曲排队输入用于检查快速路径回退和业务/计数一致性；连锁输入只将原三曲第一首改为 186 HARD，其他档案和参数保持不变。旧连锁剪枝属于已知不完整近似，不能把其候选数或最优值直接当成新算法正确性标准。

本轮脚本、结果、哈希及日志保存于 `tmp/queue-state-optimization/`；私有档案和计算数据不纳入 Git。
