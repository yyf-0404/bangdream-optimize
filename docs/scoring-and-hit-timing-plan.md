# 计分修正与击打时机优化：问题汇总和推进顺序

整理日期：2026-09-20。用户已确认按本文顺序推进。第一阶段的统一算术模块及原生对照已完成，见[第一阶段交付](scoring-core.md)；第二阶段已完成[真实输入与谱面评分独立接入](scoring-integration.md)。正式入口已改接新算术并完成本轮全规模和跨平台验收，见[迁移验收](scoring-migration.md)。击打时机优化目前在独立研究脚本中。

## 1. 建议

**先修复已有的确定性计分误差，建立统一计分基准，再继续接入击打时机优化。**

击打优化会比较很多很接近的分数。评分基础不一致时，无法区分收益来自合法击打调整、旧算法偏差还是新算法偏差；其上界、缓存与自动编队还可能重复修改。

已有研究保留：显式击打时间、允许 Great、按具体技能修正 Good/Bad、技能排队、60/120 FPS 对照、缓存评分和联合搜索都仍有价值。独立参考已采用原生逐步单精度、Fever 取整顺序和递增技能规则，修复正式引擎时可以复用这些证据。参考中的综合力入口已支持浮点输入；真实档案的逐维加成已通过固定队伍回放，正式搜索调用已迁移，验证记录见迁移验收。

| 分类 | 问题 | 状态和优先级 |

| 计分算术 | 综合力提前取整 | 已修复并完成正式入口迁移 |
| 计分算术 | 合并为 f64 倍率，改变游戏逐步 f32 的舍入位置 | 已修复并完成正式入口迁移 |
| 计分算术 | Fever 在第一段取整之前参与计算 | 已修复并完成正式入口迁移 |
| 计分算术 | 递增技能直接累加倍率，产生边界误差 | 已修复并完成正式入口迁移 |
| 显示 | 巡回总综合力先逐队取整再相加 | 已修复，独立计算显示值并在合计后取整 |
| 评分依赖 | 缓存键、控分区间、剪枝依赖整数综合力及旧连续倍率 | 已迁移浮点缓存、逆像及保守边界；不据此倒推旧档案必然误剪 |
| 时机模型 | 理想整帧结束与原生 f32 倒计时存在边界差异 | 已有固定帧对照；新功能接入前统一，不能一律补一帧 |
| 时机模型 | 同刻普通键隐含晚打 | 既有策略假设；必须显式表达，避免与新优化重复计入收益 |
| 技能数据 | 正式技能定义不能完整表达 Great 及判定修正后的状态变化 | AP 简化不能直接用于新功能；需要扩展 |

| 搜索范围 | 多个技能键联合变化、全局最优性 | 当前为条件枚举和局部改进，没有全局最优证明 |
| 计算目标 | 平均 PT 使用固定打法还是按已出现的技能顺序调整 | 尚未确定，不能默认预知随机触发顺序 |

## 3. 第一阶段：统一计分基础

状态：已完成核心算术及固定时间线结算对照；正式应用调用也已完成第二阶段迁移。验证数据、接口与剩余边界见[第一阶段交付](scoring-core.md)。

先建立正式引擎可调用的、可独立验证的评分实现：

1. 区分成员三维、用于评分的浮点综合力、用于展示的整数综合力。核对加成、逐维累加与运算顺序；不要删除所有养成取整。
2. 固定每一步单精度运算和两段取整位置，覆盖普通得分、Fever 与递增技能。
3. 将独立参考扩展到浮点综合力输入，补充能触发整数边界的样例。旧的整数样例仍保留为对照。
4. 先用固定队伍、固定技能时间线验证，把算术差异与时机差异分开。

本阶段验收：同样的输入、判定和技能状态，正式评分、独立参考与原生片段的逐键分数一致。测试包含小数综合力、整数综合力、Combo 阶梯、Fever、递增上限和乘法取整边界。通过后再迁移搜索；不能只改结果页重算。

## 4. 第二阶段：迁移原有计算与加速

当前进度：真实输入、保留现有调度的谱面评分、相同状态压缩和 AVX2 已有独立入口，并通过真实档案／原生算术对照。缓存、控分区间、剪枝及应用搜索均已迁移，详见[迁移验收](scoring-migration.md)。

后续已补充[完整浮点缓存、精确控分逆像及固定时间线的舍入上下界](scoring-search-bounds.md)，真实数据和原生边界对照通过。完整贡献模型、MITM 三维范围及实际搜索入口已完成接入。

接入指定队伍、单曲/巡回最高分、最大平均 PT、Auto 和控分，同步分数分布、推荐顺序及最高分命中概率。

- 相同状态压缩继续保留：在完整执行原生运算后复用单键结果，避免合并跨越单精度舍入的算式。
- AVX2 评分改用对应精度及步骤，再与可移植评分逐值比较。单精度有更多并行通道，不等于已经证明更快。
- 位图、队伍冲突检查、卡牌互斥等不依赖浮点评分的优化继续使用。
- 缓存必须能区分不同的计算综合力，控分不能继续假设综合力只落在整数点。
- 对贡献剪枝、兼容队伍上界及其他分数界限，推导保守误差范围并与小规模穷举对照；不直接删除贡献剪枝，也不凭经验随意加常数。

本阶段验收：各评分路径逐值一致；小样本优化结果与穷举一致；原来的新旧档案在相同条件下复测分阶段耗时、候选数和结果。正确性和性能分开记录，不能只因新旧分数接近就通过。

历史结果保留原值及原计算口径；新计算使用新的规则标识。不能因为修复公式而清空历史，也不能只更新版本文字、让旧分数被误认为按新规则计算。

## 5. 第三阶段：统一显式时机和技能语义

这部分是原引擎与新优化共用的准备工作：

- 以明确的击打帧和帧内处理顺序表达技能请求、开始、结束及延后。
- 60/120 FPS 分别验证；固定帧模型与设备实测结论区分记录。
- 将隐含晚打改成有实际时间、判定和得分代价的动作，避免把已有假设再算作优化收益。
- 正式技能数据保留判定门槛、Perfect 条件、连续判定状态、递增状态及重置时机；允许 Great 时不能一律取最大加成。

在本阶段统一规则之前，旧策略与新策略应各自明确命名和条件；不要悄悄改变时机假设后把全部分差归因于算术修复。

## 6. 第四阶段：继续击打时机优化

建议先完成固定队伍和固定触发顺序的正式评分与打法输出，再扩大到技能顺序、平均 PT 和自动编队。

1. 核实连接节点类型映射，再逐类开放可移动节点。未核实的节点继续固定，并显示研究范围。
2. 将中间小点和终点的有效期、前后依赖、隐藏节点推进组成完整连接计划。
3. 扩大多键联合搜索，并用小谱面穷举检查；没有证明之前继续表述为可执行的改进方案。
4. 确定平均 PT 的打法信息范围后，再考虑技能顺序权重和平均收益。
5. 针对新的可移动窗口重新建立自动编队上界，不能直接把旧的固定窗口贡献剪枝用于新目标。

已有 52 项研究行为测试、原生判定/技能证据和实曲打法保留。之后用同一套新计分规则分别回放“原打法”和“优化打法”，单独报告算术修正、时机模型变化和击打调整带来的分差。

## 7. 现在可以继续的独立资料工作

修复期间仍可补齐原始游戏 BMS、核实节点映射、整理连接状态证据；这些工作不依赖旧评分公式。但暂缓继续扩展基于旧评分的收益搜索、正式 UI 和自动编队接入。

**第二阶段已完成。下一阶段是统一显式击打时机与技能语义；这次未继续扩展击打优化搜索或上线相关 UI。**
