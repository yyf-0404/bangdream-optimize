# 第三队前缀的单卡 / 双卡冲突证明实验（2026-09-16）

本轮在已有 AVX2 第二层过滤、第三层前缀复用之上，尝试提前证明当前整个第三队前缀均与第二队冲突。两个版本均未采用，生产代码已经恢复至本轮实验前的扫描路径。

## 原理与边界

固定第一队后，已有实现保存与第一队不冲突的第三队前缀。实验寻找一张卡 a 或一对卡 {a, b}，使该前缀里的每个第三队都至少包含其中一张。若第二队包含这张卡或同时包含这两张卡，则整个前缀都不可能组成合法三队，可以直接跳过。

任意这样的双卡证明必然与第一个第三队相交。从其最多五张卡中选 a，再取首个不含 a 的第三队中的最多五张卡作为 b，继续维护剩余候选的交集。每个证明保存首次出现反例的位置，保证动态分数门槛下只跳过已经证明覆盖的前缀。每个第一队最多保存 30 条规则，不构建候选两两关系表。至少覆盖八个已过滤第三队才保存规则。

第一版按覆盖截止位置从大到小查询全部规则。第二版仍生成规则，但只查询覆盖范围最大的一条。没有证明时继续原 AVX2 扫描；候选顺序、相等分数边界和逻辑检查计数保持不变。

## 完整档案对照

沿用当前加权 96 种排列概率模型、精确搜索，以及此前所有已经保留的评分和剪枝优化。原生 Rust Release，Ryzen 5 5500U。两份冻结输入分别是 1456 卡活动 323（186 SP / 395 SP / 772 EX）和 1414 卡历史 fixture（306 EX 三曲）。

每版每个档案分别开启、关闭一次；同一版内每份档案使用同一二进制。执行顺序均为新档案开启 → 关闭、旧档案关闭 → 开启，没有额外预热，计时不与编译或测试并行。

| 版本 | 档案 | 三队阶段关闭 → 开启 | 完整计算关闭 → 开启 | 跳过二队分支 |
|---|---|---:|---:|---:|
| 全规则 | 1456 | 9.776 → 15.285 s | 36.238 → 38.903 s | 330,912,689 |
| 全规则 | 1414 | 4.363 → 6.108 s | 19.647 → 21.531 s | 128,022,270 |
| 只查一条 | 1456 | 12.208 → 10.316 s | 38.565 → 35.481 s | 63,839,747 |
| 只查一条 | 1414 | 5.152 → 5.661 s | 23.121 → 25.072 s | 36,770,831 |

全规则版虽然消除了大量分支，但每次查询多个规则的开销超过了节省的扫描时间。只查一条显著减少查询成本，却也大幅减少命中；在旧档案上仍没有收益。未修改的候选阶段也出现波动，单轮数据不足以认定第二版在新档案上的改善稳定。因此本轮不将这些规则加入默认搜索器，也不据此宣称冲突预判在所有输入上都无效。
