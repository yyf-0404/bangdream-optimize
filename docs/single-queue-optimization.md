# 单曲编队接入排队状态优化（2026-09-17）

## 接入范围

单曲最高分和单曲平均 PT 的自动编队共用此前完成的排队判定区间与状态表，支持标准时长的非连锁、连锁排队。指定队伍的顺序与队长约束保持原有语义。

- 最高分：恢复排队贡献剪枝；按技能位采用所有可达排队状态的连续评分上界；精确叶子通过六次状态转移查分，不再为每种排列编译整张谱面的倍率数组。
- 平均 PT：恢复模式与分支上界；排队队伍进入摘要评分和安全截断路径；复用状态计划缓存。仍按每个排列的实际整数分数和洗牌权重计算 PT，不以平均分代替平均 PT。
- 计分缓存：同一综合力下，复用相同技能、相同判定区间的整数贡献；相同基础倍率区间使用压缩计分。保留 Fever 的逐键取整语义。最多缓存 128 个综合力值，达到容量后清理；缓存只在本次单曲搜索内存活。
- 普通无排队路径继续使用原有评分器。标准集合外的时长采用保守上界和完整时间线，不能用其他标准技能的缓存上界剪掉这些输入。

多人协力有四名外部玩家技能，其排队贡献剪枝继续保守跳过。带 PT 加成的单人演奏，排队剪枝要求分数支配且 PT 加成不下降；不套用独立窗口下的分数与加成交换公式。

## 一并修复的比较边界

`AveragePt` 原来的相等比较按分子、分母字段比较，排序则按分数值比较，两者不一致。`239/1` 与 `244736/1024` 因此可能走入“不相等且不大于”的分支，被提前剪掉，错失同 PT 下更高的平均分数。现在相等与排序统一使用无溢出的有理数比较，输出的分子、分母保持原样。

## 验证与复测方法

回归以完整技能排队时间线为正确性基准：覆盖全排列和所有队长、手动与自动规则、Fever、爬分、缓存淘汰，以及不剪枝枚举所有合法五卡队伍。平均 PT 另检查加权直方图与相同 PT 下的平均分数次目标。

性能对照使用 `experimental-single-queue` 功能和 `BANGDREAM_OPTIMIZE_SINGLE_QUEUE_BASELINE=1`。同一原生 Release 二进制在不同进程内开关本次单曲接入，生产环境不编译关闭开关。两侧均包含上述分数比较修正和相同技能 Meta 的准备缓存。

复测目录：`tmp/single-queue-optimization/`。输入沿用 1,456 卡档案与 323 活动的加成、道具数据，将单首谱面传给单曲内核；固定 Pastel＊Palettes、Cool、演出杂志，遍历全部技能统一模式。最高分比较严格五卡搜索；平均 PT 分别使用挑战活动 CP 演奏和普通单人演奏公式。PT 对照逐模式独立调用内核，未共享跨模式的当前最优值。这不是把 323 活动当作单曲活动，也不是全道具或 WASM 的端到端耗时。

计时从搜索内核入口开始，包含卡池剪枝和所有模式的搜索，不包含 JSON 读取、档案准备和谱面初始化。每项记录一轮，两侧串行运行，同一二进制、相同输入。

无排队几十毫秒级的差异不视为确定的加速。排队谱面的主要收益来自恢复贡献剪枝及分支上界：此前 PT 的排队路径甚至不启用分支评分上界，因此旧版完整档案无法在本轮时限内完成。不同谱面的原有上界松紧程度不同，不能将上述倍数推广到所有谱面。

`*_2-run.json` 保存输入及二进制 SHA256、计时和对照状态，`*_2.log` 保存最高分搜索的分阶段信息。较早的 `*_1` 是仅运行 Mixed 模式的无解入口试跑，未纳入表格。中止的连锁 PT 记录也未作为耗时下界或正确性对照。
