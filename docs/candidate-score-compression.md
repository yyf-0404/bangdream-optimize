# 相同倍率压缩评分与候选枚举（2026-09-16）

本轮按照用户提出的“压缩相同倍率”优化评分，接入巡回候选枚举和平均分候选转换。普通技能按连续相同评分系数的区段计数，保留逐音符评分的两次取整；递增技能仍保留每个音符的倍率，并使用 AVX2。没有使用跨队伍得分结果缓存。

两份完整档案的原始枚举耗时均减少约 48%，整个候选阶段减少约 33%。本轮没有修改候选范围、枚举顺序、剪枝规则、18500 分带、概率权重或三队搜索算法。

## 同轮完整计算

原生 Release，Ryzen 5 5500U，Rust 1.93.1，单线程搜索。每份档案使用同一个可执行文件开关评分压缩；关闭时保留相同的谱面区段预处理结构，实际候选评分使用原逐音符 AVX2 路径。两侧三队搜索均固定为上一轮的 AVX2 第二层批量过滤与第三层前缀复用，关闭倒排位图实验。不是旧 120 种等概率模型对新模型的比较。

## 压缩方法

初始化谱面时，只合并浮点位模式完全相同的相邻基础系数，不使用误差容限。记录每段的系数、起止位置；编译技能窗口时同时记录对应区段范围。对于覆盖了 n 个相同系数 a 的普通技能音符：

```text
b = floor(stat * a)
delta = n * (floor(b * (1 + score_up)) - b)
```

这与逐个音符相加严格相等；不能把取整挪到乘以 n 之后。技能只覆盖区段一部分时，使用窗口与区段交集的实际音符数。

递增技能的倍率在音符之间不同，不能直接套用普通技能的计数。实现复用原来的倍率递增序列及上限处理，以区段内相同基础分配合逐音符倍率做 AVX2 运算，非 x86 / 无 AVX2 时使用标量回退。没有把逐次浮点加法替换成另一条解析公式。

- 新档案三曲：800 → 12、774 → 8、640 → 8 个基础评分项。
- 旧档案三曲：772 → 12、772 → 9、772 → 9 个基础评分项。
- 普通技能只遍历其覆盖的倍率区段；无需为每个音符重新算技能加成。
- 相同技能效果的卡牌在同一个矩阵内共用整行增量。
- Fever 或请求计分模式与初始化模式不一致时回退原实现。
- 严格排队技能的回退语义不变；最高分并列时仍优先保留原 meta 种子顺序与队长。
- 新增存储是谱面区段及窗口索引，规模取决于谱面，不随枚举队伍数增长。

基础项压缩到约 1/70 并不代表整个枚举提速 70 倍。递增技能、五卡排列求解、meta 种子顺序、角色组合枚举和候选过滤仍需执行。

- 两份档案所有非计时结果字段及逻辑搜索计数，既与同轮关闭模式一致，也与上一轮冻结 AVX2 复用结果一致。
- 保留候选累计 824,837 / 390,430；合法三队 46 / 36；精确分布数 70 / 42，均未改变。
- WASM core 编译通过；输出 4 条 solver、3 条 core 的既有未使用代码警告。本轮性能测量是原生 Rust，不是浏览器 WASM，未声称浏览器获得同等比例提升。
