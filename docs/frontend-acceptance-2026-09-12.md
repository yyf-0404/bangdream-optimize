# 前端接入复验 · 2026-09-12

基准是最终 `boundary-design` 联动预览及其中确认的发布时间、语言、草稿和共享卡牌规则。最新正式页运行于 `http://127.0.0.1:8093/?design=29#activity`。下文前半部分保留此前复验记录；文末为本次直接复制设计稿后的重新验收结果。

本次实际发现了交互遗漏与样式覆盖冲突。以下记录区分浏览器实测、规则测试和环境限制；不将“测试通过”等同于每一种数据与设备下的像素完全一致。

## 尚不能计为端到端通过的部分

1. 当前静态预览服务的桌面下载列表接口返回 HTTP 404。错误状态可见，但没有成功下载客户端。需要具备发布清单的运行环境复验。
2. 真实游戏账号导入成功路径未使用有效玩家 ID 测试；ID 缺失的前置提示已复验。跨服账号接口可达性仍需有效账号和对应服务环境验证。
3. 没有执行“删除全部档案”、清空现有计算历史、发送反馈或全量资源更新。仅检查入口/说明/确认和相关规则，避免验收破坏原数据或发送真实报告。
4. Tauri 客户端启动、本机文件保存对话框、离线网络故障及浏览器存储配额耗尽未进行本次浏览器端故障注入，不能用这轮结果替代桌面端验收。
5. 控分实测覆盖非法范围及合法无方案输出，未获得这份样本的精确命中方案。实际命中方案展示还有既有结果显示测试覆盖，不能宣称已完成浏览器命中路径验收。

自动审批曾将筛选按钮“恢复档案默认”误判为重置持有数据。核对 `catalog.js` 的事件绑定后，确认只保存界面筛选偏好，重试获得允许；没有绕过审批执行数据重置。

## 直接复制设计稿后的复验（版本 29）

本次按用户要求改变接入方式。`design.css` 不再加载旧 `styles.css`、`redesign.css` 两套全局样式，而使用 runtime → bindings → approved → plumbing。设计稿样式优先于旧节点适配；最后一层只处理 SPA 的页面显隐、滚动、容器和真实控件别名。

`scripts/import-design-markup.py <设计工作区>` 直接提取最终稿的 15 个静态片段，并复制演出设置、计算参数、侧栏、批量养成、档案新建/导入/核对/完成/导出等动态模板，以及结果装饰函数。`scripts/sync-approved-design.py` 导入对应 CSS。来源 SHA256 记录在 `src/ui/approved/markup-sources.json`；没有把 PreviewSession、模拟求解器或固定样例数值接入正式页面。动态数据、列表分批渲染、档案持久化和 WASM 求解继续使用正式逻辑。

### 本次发现并修复

- 演出设置标签被旧绝对定位样式压成窄条：改为源模板，并移除两套全局旧样式的干扰。
- 计算参数的数字输入在后续选项切换时可能退回旧值：数字合法时即保存，输入期间保留焦点和原输入节点；演出设置的支援加成同步采用此方式。
- 去掉旧 CSS 后，批量养成、反馈和确认弹窗仍依赖旧结构：均换成源模板及对应原稿 CSS。批量全选按钮仍保持固定“全选”文案和原先的范围切换语义。
- 结果难度丢失 D 方案：活动和结果共用难度组件，恢复原稿类名、颜色及空心/实心状态。
- 档案导入仍是旧版多个提交按钮：换成原稿来源页签、读取预览、差异表、当前/新建目标和完成页；导出采用原稿格式选项、真实只读内容、复制与下载按钮。账号导入字段仅在应用后落盘；读取失败保留草稿并就地提示。
- 原稿 SVG 直接从源文件导入，避免图标名称缺失时变成通用图标。
