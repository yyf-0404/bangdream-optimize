# 原生评分：候选存储与摆放分组优化

日期：2026-09-20。接续 [剪枝收紧与旧版对比](scoring-pruning-tightening.md)。本轮只减少重复存储、复制和堆分配，不修改评分算术、上下界、技能延后模型、候选枚举或搜索规则。

## 改动

- 原始三队候选不再内嵌五人的 `MemberPower`。综合力数据由当前道具组合按卡牌保存；原始候选保存原始卡牌索引。在平均 PT 的分数带筛选完成后，再从同一份卡牌及道具数据恢复存活候选的综合力。最高得分的原始候选本来就不再读取这份内嵌数据。
- `groups_for_charts` 的常见单组结果改用栈内存，避免每个候选创建并释放一个只有一项的 `Vec`。只有多个不同综合力确实需要分别评分时才使用动态数组。原有的第一段整数键分等价证明、全部 120 种摆放及可达掩码不变。
- 平均 PT 的最低综合力过滤仍能修改或删除单组/多组结果；单曲摆放缓存共用同一表示。显示路径所需的成员原始三维及道具/活动分项并未删除，只是不再复制进每一条原始候选。

## 验证

- Release 构建：核心 244、数据层 28、三队求解器 23、WASM 接口 10，共 **305 项通过**；保留原有 11 项忽略项。
- 重建实际 WASM 后，10 组与原生正式入口逐字段一致，覆盖单曲/巡回最高分和最大平均 PT、指定队伍手动及 Auto、技能延后、协力和非空控分结果。
- 下方三版本四场景共 12 份输出，与对应版本的既有输出一致，仅排除 `metrics` 和 `solver`。本轮优化前后的全部候选数量、检查次数、exactWork 及其他非计时指标一致。
- 网页资源标识更新为 `native-f32-3`；计分规则标识和结果缓存版本不变，因为计算结果未变。

调试构建首次遇到磁盘空间不足，清理了项目内可重建的 `target/debug/incremental` 缓存。随后调试回归的大候选用例耗时过长，中止该轮并用与之前一致的 Release 构建完整重跑；以上通过数量来自完整结束的 Release 运行，不将中止的调试运行算作通过。

## 同轮三版本基准

Windows 原生 Release，固定同一逻辑核（掩码 4）、相同进程优先级。每场景每版本一轮，三版本顺序按场景轮换，全程串行，计时期间不进行构建或其他测试。最高分强制精准搜索；平均 PT 使用相同加权概率模型。

- 旧整数版：提交 `1685a950bdf5fc88205256d53664ad3f3797af7a` 的 0.4.5。
- 本轮之前：已完成原生 f32 迁移及上一轮安全剪枝收紧的版本。
- 本轮之后：删除重复综合力存储、单组摆放结果避免动态分配。

### 峰值内存

由 Windows `GetProcessMemoryInfo` 记录每个子进程的峰值工作集（MiB，除以 1,048,576）。完整记录另含峰值提交内存。

| 档案 / 目标 | 旧整数版 | 本轮之前 | 本轮之后 | 本轮下降 |
| --- | ---: | ---: | ---: | ---: |
| 1456 / 最大平均 PT | 139.68 | 291.34 | 138.45 | 52.5% |
| 1456 / 最高得分 | 139.96 | 290.96 | 138.59 | 52.4% |
| 1414 / 最大平均 PT | 152.65 | 309.17 | 157.30 | 49.1% |

### 阶段与 CPU 时间

| 档案 / 目标 | 候选构建：前 → 后 | 三队搜索：前 → 后 | 进程 CPU 时间：前 → 后 |
| --- | ---: | ---: | ---: |
| 1456 / 最大平均 PT | 51.796 → 44.812 s | 19.313 → 16.684 s | 78.469 → 68.641 s |
| 1456 / 最高得分 | 41.706 → 41.855 s | 15.720 → 13.919 s | 64.719 → 62.703 s |
| 1414 / 最大平均 PT | 40.179 → 39.569 s | 9.975 → 10.242 s | 55.656 → 53.625 s |
| 1414 / 最高得分 | 31.336 → 23.004 s | 7.902 → 5.119 s | 44.750 → 35.250 s |

耗时仍有明显波动。尤其新档案最高分的候选构建没有实测改善，不能把 2.6% 的总耗时变化当成稳定收益，也不能把其他场景的 24.6% 推广到所有情况。三队算法和检查次数未改，三队阶段的时间变化不能解释成剪枝工作量减少。

相对旧整数版，前三组本轮仍慢约 29%、43%、34%。旧档案最高分墙钟时间接近，但其 CPU 时间仍为 35.250 s，对比旧版 31.844 s，高约 10.7%，因此不宣称全面追平旧版。下一步若继续优化，应优先细分候选评分内的校验、综合力分组、技能矩阵及上界计算成本；本轮没有放弃浮点边界或减少合法候选。

原始输入、日志、12 份输出、二进制哈希、CPU 周期和复测脚本保留于忽略目录 `tmp/native-candidate-tightening/`，入口为 `compare.py`，汇总为 `benchmark-candidate-comparison.json`。玩家档案不进入版本管理。

完整档案的控分补测见 [浮点评分迁移后的控分基准](scoring-control-benchmark.md)。控分使用独立的 MITM 与区间反求路径，本轮候选存储优化没有为其带来稳定加速。

组队各类缓存和摆放分组的实际命中情况，见 [浮点缓存审计](scoring-cache-audit.md)。
