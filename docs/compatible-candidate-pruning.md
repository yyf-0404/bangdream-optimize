# 兼容性与两队合计上界剪枝（2026-09-16）

本轮增强巡回平均 PT 的候选队伍剪枝。在现有分数带筛选后，加入当前队伍与另外两队的卡牌兼容上界，以及另外两队彼此不重复用卡的合计上界。生产代码默认启用，原始枚举、技能概率、18500 分带和最终精确评价规则保持不变。

## 完整档案对照

原生 Rust Release，Ryzen 5 5500U，Rust 1.93.1。使用此前冻结的两份完整档案：

- 1456 卡：国服活动 323，按活动顺序使用 186 SP / 395 SP / 772 EX。
- 1414 卡：历史基准档案，自定义活动 0，306 EX 三曲。

两侧都使用当前 96 种排列 / 1024 条路径概率、相同倍率压缩评分、上一轮覆盖 DP 优化，以及 AVX2 第二层过滤与第三层前缀复用。这里的“关闭”只关闭本轮新增剪枝，并非恢复旧的 120 种等概率模型。

## 上界与安全性

设候选 A 分配到歌曲 a，另外两曲为 b、c，当前整数门槛为 F。

原筛选使用 `score_a(A) + max_score_b + max_score_c`，后两项可能来自与 A 重复的卡牌，也可能来自彼此重复的两队。

新增两类上界：

1. `U_b(A)`、`U_c(A)`：分别排除 A 的五张卡后，对另一曲可达分数的上界。
2. `P_bc = max_B(score_b(B) + U_c(B))`：对 b、c 两队互不重复用卡时合计分数的上界，此时暂不限制它们是否与 A 重复。

最终检查：

```text
score_a(A) + min(U_b(A) + U_c(A), P_bc) >= F
```

只要 A 在任意一首歌上通过就保留，只有三首都不能达到门槛才删除。初始种子中必须保留的队伍仍由原逻辑保留。

任何合法三队 A、B、C 都满足：B、C 分别不与 A 重复，因此 `U_b(A) + U_c(A)` 不小于其实际合计分数；B 与 C 也不重复，因此 `P_bc` 同样不小于其实际合计分数。两个上界取最小值仍是上界。这没有声称两种约束合并后已经求出最优三队。

原始候选阶段用每曲最高分乘 1024 作为平均分分子的上界；平均分转换后使用实际的最大加权平均分子。全程整数比较，恰好等于 F 时保留，没有增加近似阈值或改变 18500 规则。

## 查询成本

- 将活跃卡牌的位置压缩为连续编号，避免为完整档案的所有卡牌分配倒排表。
- 每曲按得分降序建立索引，每张卡一行位图；合并当前队伍五行的冲突位后，找到第一个可用候选。
- 预先记录每张卡第一个未完全覆盖的位图字，从五张卡对应位置的最大值开始查找，跳过必然冲突的前缀。
- 每曲冲突位图最多使用 8 MiB，三曲合计最多 24 MiB；这是位图预算，其他候选、排序和查询缓存另占空间。超出预算只索引得分最高的前缀。
- 如果前缀内没有兼容候选，使用未检查尾部的最高分作为上界。只有全部候选都已检查且确实没有兼容队伍时才返回无解，截断不会造成误删。
- 所有候选的三曲兼容查询结果复用于两队合计上界，不再枚举一次候选对。保留列表仍按原顺序输出。

## 试验过程

先试过仅排除当前队伍卡牌、最多检查前 4096 个候选的版本。1456 档案累计保留量降至 425,494，但三个主池仍为 157,875 / 129,151 / 138,468，几乎未变；1414 档案仅降至 383,047。

扩大查询深度后，两份档案的保留数量仍相同，查询成本反而上升。这说明瓶颈主要在另外两队相互冲突，而不是查找深度。加入两队合计上界后得到最终结果。前两轮只作为方案比较，不与最终同轮关闭计时混算加速比。

## 正确性核对

- 两份档案的所有最终非指标字段均逐项相同，包括三支队伍、道具、推荐顺序、队长、分数分布、总分分子和 PT 范围。
- 1456 卡平均 PT 精确保持 `728394032679 / 1073741824`；1414 卡保持 `789280615173 / 1073741824`。
- 原始候选的队伍索引、三曲分数、技能顺序、队长和综合力的逐批指纹全部相同：1456 卡 38 批共 5,860,064 条；1414 卡 21 批共 3,693,336 条。
- 新增 5 项测试。64 组随机池各 70 个候选，覆盖 0 / 1 / 7 / 63 / 64 / 65 / 70 的索引截断；逐一枚举合法三队，验证能达到门槛的每个成员都保留。另检查门槛相等、空池、尾部填充位、连续两个完全冲突的位图字、稀疏卡牌编号和原始列表顺序。
- core 全部测试：185 通过、1 项原有压力测试跳过。WASM core 编译通过，保留原有 4 条 solver、3 条 core 未使用代码警告。本轮没有测浏览器内的 WASM 性能。

最终分带仍使用 AVX2 完整扫描。候选缩小后，种子搜索的候选顺序和规模会影响其初始方案；本轮 1456 档案的合法计划计数从 46 变为 43、分布缓存从 70 变为 67，最终结果仍完全相同。不能要求逻辑计数在增强剪枝后全部不变。

## 范围与剩余成本

本轮改动位于巡回平均 PT 的原始候选分数带筛选和平均分带筛选。没有改最高分目标、单曲目标或多人协力模型；没有减少原始五卡组合的枚举总量。

候选数量下降不等于三队检查量按同样比例下降：1456 档案第三层逻辑计数从 228.21 亿降至 197.85 亿，1414 从 50.63 亿降至 47.69 亿。高分候选内部仍存在大量冲突，原始枚举和这些高分组合仍是后续可研究的成本。
