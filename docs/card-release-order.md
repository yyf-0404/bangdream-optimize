# 卡牌发布时间排序

确认规则（2026-09-17）：先建立同服的先后关系，保留经其他卡牌连接的间接关系；不能因为两张卡没有共有服务器就直接比较各自日期。

例如，降序下 `2480 → 2353 → 10052`：前一段由日服日期确定，后一段由国服日期确定。即使筛选隐藏了 2353，也保留 2480 在 10052 前面的关系。

## 实现

- 使用完整卡库的发布时间，不依赖当前档案服务器、持有状态、角色、稀有度、搜索条件或分组。未来日期参与排序，服务器筛选的未来七天窗口仍单独处理。
- 按日服、国服、国际服、台服、韩服的优先级建立有向无环图。同服按日期分桶，仅连接相邻日期桶；间接路径保留更远的先后关系。同日期卡牌不互加日期约束。
- 每个服务器按日期新到旧、桶内 ID 降序处理约束。如果新约束会形成循环，忽略这条约束，保留此前已经接受的高优先级关系。已经存在间接路径的约束无需重复加入。
- 分别对图及其反向图进行拓扑排序。当前没有未满足约束的卡牌，按各自最早有效发布时间选择，新旧方向跟随排序方向；同日期按 ID 降序。无有效日期的卡牌在两个方向都排最后。
- 主关键字仍按用户选择的持有状态、稀有度或 ID 排序；发布时间作为原有的第二关键字。日期排序的名次表在筛选和分组之前生成。
- 卡牌列表、队伍选择和指定加成卡牌选择共用此规则；封面选择同样先使用完整卡库确定名次，再限定已持有卡牌，自动模式继续跳过二星卡。

核心文件为 `apps/web/src/ui/cards/release-order.js`。缓存只包含归一化后的卡牌 ID 和五服日期，养成、持有及语言变化不重建关系；新增卡牌或修改日期会自动失效。构建时使用临时可达性位图检查循环，约 2,500 张卡时占用 0.75 MiB；构建完成仅保留升、降序名次表。

## 验证

- 新增 8 项规则测试，覆盖独占卡的间接连接、跨五服关系、服务器优先级冲突、无关联回退、同日期、缺失和未来日期、缓存失效以及输入枚举顺序无关性。
- 148 项前端测试通过。
- 本地 2,461 张真实卡牌完整试排通过；日服时间顺序保留、两方向无遗漏、输入倒序不改变结果。筛掉中间卡和自动封面选择均覆盖测试。
- 一次 Node 测量：完整关系构建约 210 ms，同元数据再次读取约 10 ms；仅为本机单次测量，不是跨设备性能保证。
