## 改动原理

每首曲子的矩阵是五张卡、六次触发。前五次触发需要将五张卡各分配一次，第六次为队长重复触发，可以独立取最优队长。

原实现用通用子集 DP：遍历 31 个来源状态，运行时计算已分配人数、尚未使用的卡牌位、目标状态，然后执行 80 次转移。该过程会在每个候选的三曲精确评分中重复执行，也会用于未命中初始顺序缓存时的浮点评分。

新实现位于 `crates/core/src/skill_assignment.rs`，使用同一份宏生成整数与浮点两种分配函数：

- 显式列出目标状态 1 至 31，编译期确定触发位置及所有前驱索引。
- 仍执行原来的 80 次转移，由编译器消除固定条件、位扫描和动态索引开销；没有减少搜索范围，也没有改用贪心或近似分配。
- 整数版本接入 `model/chart.rs` 的精确技能分配，浮点版本接入 `medley/scoring.rs` 的初始顺序计算。
- 保留技能行完全相同时的快捷路径、队长同分选择和最终顺序回溯。
- 沿用固定大小的栈数组，不增加堆分配或缓存。代价是增加展开后的机器码；WASM 编译可检查兼容性，但不能由原生测试推断其运行收益。

## 同分与浮点一致性

原算法按来源集合编号升序更新每个目标集合，只有新值严格更大时才替换。对于目标集合 M，所有来源为 `M ^ (1 << card)`；来源升序恰好对应移除卡牌位从高到低。

因此新算法对每个目标按卡牌 4 → 0 检查前驱，继续使用严格的 `>`。目标的每个前驱都是更小的集合，已经计算完成；前驱值、相加的两个操作数、比较顺序及同分选择都与原算法相同。浮点版没有重排某条路径中的累加顺序，也没有使用误差阈值。

队长仍按卡牌 0 → 4 选第一个最大值。原有的“如果初始顺序也达到精确最高分，就保留初始顺序”逻辑继续由调用方执行。

- 两轮各开关模式的输入和二进制哈希相同；计时结束后核对源码哈希，确认没有代码漂移。

本轮完整档案计时仍以巡回平均 PT 为准，未测浏览器或桌面 UI 的端到端时间。

## 小型实验与适用范围

先用独立整数 DP 原型测试 10,000 组矩阵，每次执行一百万次分配，四轮交替顺序测得原循环约 227–235 ms，展开版约 53–57 ms。这仅用于筛选方案，没有将局部约 4 倍加速当成完整引擎加速比。

该修改针对固定五卡矩阵的分配函数；没有新增候选剪枝或修改三队扫描。初始顺序缓存和精确评分矩阵构造之后，仍有大量计算不能由 DP 展开消除。
