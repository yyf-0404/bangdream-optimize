# 指定队伍 PT 计算

## 目标与边界

`ptEvaluate` 使用玩家显式选定的队伍、谱面和区域道具，精确计算 5 个队员技能等概率排列下的最低、最高与平均分数/PT。它与队伍搜索的 `ptMaximize` 并列，不枚举卡牌和道具。

支持的场景：

- 任务 Live、EX：自由演出；
- Challenge：自由演出或挑战演出；
- 竞演：自由演出或竞演演出；
- 5v5：仅自由演出；
- 组曲：仅三曲巡回演出。

不支持协力演出和团队演出，因此指定队伍路径不计算 Fever。

## 请求和校验

`PtEvaluateRequest` 包含活动/演出模式、歌曲、队伍、三类道具、手动/Auto 计分方式及模式特有参数。后端以活动数据中的活动类型为权威值，不信任客户端传入的 `eventType`。

计算前必须满足：

- 单曲模式恰好 1 张谱面和 1 支队伍；巡回演出恰好 3 张谱面和 3 支队伍；
- 每支队伍恰好 5 张不同卡牌、5 个不同角色；
- 前端第三个卡位固定为队长，`captainCardId == cardIds[2]`，后端再次校验；
- 组曲的 15 个卡位不能复用同一张物理卡，但允许同角色的不同卡牌跨队使用；
- 乐队、属性、杂志道具都必须选择；任一装备组含 0 级组件时拒绝计算；
- Auto 基础倍率仅允许 0.5 和 0.75，日服默认 0.75，其他服默认 0.5；
- 任务 Live 需要支援乐队 PT 加成，竞演演出需要合法排名。

## 精确计分

手动演奏使用理想 60 FPS、全 Perfect 与完整 Combo；Auto 复用控分的无 Combo 规则和服务器基础倍率。两者都复用统一的精确技能窗口和排队计分内核。

对无排队的谱面，先构建无技能基础分与 `5×6` 技能增量矩阵，再用 32 状态子集 DP 生成 120 种排列的分数分布。有排队时，逐个枚举 120 种排列并调用同一精确计分内核。第六个技能始终使用第三卡位的队长技能。

组曲每曲独立产生分数直方图，再按三曲 PT 公式在直方图上合并；不假设三曲得到相同 PT。

## 主乐队导入

所有服务器都调用既有 `mode=3` 主乐队资料接口。导入必须同时获得 `mainUserDeck` 与 `mainDeckUserSituations.entries`，不根据综合力或数组顺序推断队长。

固定映射顺序为：

1. `member3`
2. `member1`
3. `leader`
4. `member2`
5. `member4`

导入会覆盖返回卡牌的等级/技能/突破/剧情状态，对应角色加成等级及返回的区域道具等级，并同步当前三类道具选择。组曲的三支队伍各有独立导入按钮。

## 返回与展示

单曲返回整体最低/最高/平均 PT 和分数，组曲另返回每曲最低/最高/平均分数。结果页还展示歌曲、队伍与队长、综合力、活动 PT 加成、道具及计分方式。

结果倍率仅改变展示的 PT/CP：挑战演出支持 200/400/800/1600 CP，其他单曲支持 0/1/2/3/10 火，组曲支持每曲 0/1/2/3 火。

`ptEvaluate` 全部表单值随玩家配置持久化，并连同队伍、道具、Auto 参数和模式特有参数进入结果缓存键。
