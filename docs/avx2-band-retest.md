# 平均 PT 的 AVX2 整批冲突跳过：性能复测（2026-09-16）

本次只改窄 / 宽 AVX2 近优带扫描：当四个候选全部冲突、且四项都在当前分数带内时，一次累计四项逻辑计数并跳过；跨越分数下界的批次保留逐项边界处理。候选生成、18,500 分数带规则、动态下界、技能概率和精确 PT 评估没有改变。

## 本轮判断

整批冲突快路径在两份完整档案和两个历史候选样本中都减少了扫描耗时，且没有改变精确结果。

位图相对修复后的 AVX2，在新档案的扫描中仍少耗时约 25.9%，但旧档案中多耗时约 63.3%；156,257 候选的窄掩码样本也是 AVX2 更快。因此保留 AVX2 为默认、位图为实验实现，现有样本尚不足以制定通用自动分流规则。

整批跳过缩小了平均 PT 与最高分内核的差距，但尚未完全消除：156,257 候选的同界限无命中扫描仍是 2.595 秒对 1.539 秒。该样本没有执行合法方案回调，剩余差距不能归因于概率分布或精确 PT 计算；下一步若继续优化，应在这个固定样本上拆分剩余扫描开销。

## 精确性与复现边界

- 两份完整档案、三种实现的全部非计时字段逐项一致：精确平均 PT 分子 / 分母、PT 范围、卡牌、队长、推荐顺序、候选数、逻辑检查数、合法方案数与分布缓存计数。Python 整数比较避免 JSON 大整数经 JavaScript 丢失精度。
- 修改完成时的 solver 单元测试为 19 项通过、2 项忽略；新增对照覆盖窄 / 宽 AVX2、整批冲突、恰好落在分数带下界、尾部不足四项、动态提高下界、提前停止及饱和加法。此次复测期间未再修改引擎源码，已核对构建前后源码哈希一致。
- `pairCheckCount` 和 `thirdCheckCount` 仍保留逐候选位置的逻辑计数，整批跳过也累计四项；它们不是优化后的实际位运算次数。
- 修复前后均走 AVX2；新档案三个主要池使用 `Avx2Wide`，旧档案三个主要池使用 `Avx2`。
- 新档案固定国服活动 323，186 SP / 395 SP / 772 EX，输入 SHA256 为 `6f956ba69e10df7323e177378e59c43e753bcce6b8d637d2d04b8267beaa4313`。
- 旧档案为仓库 1,414 卡诊断 fixture，其自定义活动、306 EX × 3；全部使用当前加权模型，不与历史等概率计时混算。
- 本次不含桌面窗口与前端准备耗时，不是 WASM 性能测试。此次快速路径位于 x86 AVX2 分支，WASM 的标量路径没有改变。
- 位图仍是默认关闭的实验特性。此次复测不修改自动分流阈值，不提交、推送或部署。
