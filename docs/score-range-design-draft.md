## 1. 目标与支持范围

`score_range` 根据活动参数、用户档案、候选队伍和候选歌曲，寻找能精确得到目标活动 PT
的演奏方案。它与 `maximize` 并列，拥有独立的活动支持范围、歌曲计分规则和方案搜索策略。

支持的活动类型：

- `medley`
- `versus`
- `challenge`
- `live_try`
- `festival`
- `mission_live`

这里的“全部活动”仅指 score-range 的六个 `EventType`。`maximize` 继续保持原支持范围；Festival 最大化所需的 fever 计算不在本次重设计范围内。

方案约束：

1. 整个方案使用同一支队伍。
2. 整个方案只重复一种 `(song_id, difficulty)`；不同难度视为不同歌曲。
3. 同一歌曲重复演奏时，每局可以选择不同火倍率。
4. 火倍率允许 `1`、`5`、`10`、`15`。
5. 所有可行方案先全局最小化演奏次数，再在演奏次数相同时最小化实际总火耗；`1/5/10/15` 倍分别消耗 `0/1/2/3` 火。
6. 不再搜索两种歌曲或完全背包方案；单曲无解即返回无解。

## 2. Auto 歌曲计分规则

`score_range` 使用独立的 Auto 计分规则：

1. 仅替换当前基础计分公式中的 `1.1`：使用请求选择的 `0.5` 或 `0.75`；旧请求未指定时日服使用 `0.75`，其他服务器使用 `0.5`，其余基础公式保持不变。
2. 不计算 Combo 加成，所有键的 Combo 倍率视为 `1`。
3. Rate-up 技能与标准计分一样按经过的键数增长；取消 Combo 加成不改变其增长方式。
4. 同一时刻存在技能键和其他键时，其他键先结算，技能键后结算，使同一时刻的其他键
   不获得本次刚触发的技能加成。
5. 实现上将同一时间的技能节点排到普通节点之后。

当前共享 `Chart` 默认在相同时间将技能节点排在普通节点前，因此 Auto 规则必须显式配置，
不能修改默认行为，否则会改变 `maximize` 的结果。

建议模型：

```text
ScoreRule::Auto(auto_base_multiplier)
  base_multiplier = auto_base_multiplier
  combo_mode = None
  rateup_mode = PerNote
  simultaneous_skill_order = AfterNotes
```

倍率由前端目标 PT 配置选择；服务器只在旧请求未提供倍率时决定默认值。`ScoreRangeSong` 初始化、倍率分组、精确计分和区间反解必须使用同一个请求倍率；任何跨请求缓存都必须把定点化后的 `base_multiplier` 纳入键。技能尾部风险筛选只依赖时间和 duration，不受该倍率影响。

## 3. 活动加成的两种计算模式

当前最大化计算将综合力拆为：

```text
基础综合力 + 区域道具加成 + 活动综合力加成
```

对于存在活动 PT 加成倍率的活动，活动加成不进入综合力，而是形成 PT 加成倍率 `B`。

已确认的 PT 加成规则：

1. 基数为 `100%`。
2. 五张卡各自命中的活动加成直接相加。
3. 计入属性加成。
4. 计入角色加成。
5. 计入活动 `members` 指定卡面加成。
6. 同时命中属性和角色时，计入双加成的 `20%`。
7. 计入突破等级加成。
8. 不计算双加成的偏科综合力加成（`eventCharacterParameterBonus`）。
9. 先将五张卡的所有 PT 加成百分比求和，再以 `100%` 为基数形成倍率；不逐卡取整。
10. 这些活动加成不再重复加入卡片综合力。

需要在准备层同时产出：

```text
PreparedEventContext
  cards_with_stat_bonus       # 无 PT 倍率活动使用活动综合力加成
  cards_without_event_bonus   # 有 PT 倍率活动使用
  point_bonus_multiplier      # 100% + 五卡 PT 加成之和
```

`live_try`、`challenge` 和 `mission_live` 使用 PT 加成倍率模式；`medley`、`versus` 和 `festival` 使用活动综合力加成模式。

## 4. 队伍签名与技能分桶

新的处理顺序：

1. 根据活动参数和用户档案准备卡片中与区域道具无关的基础数据。
2. 在外层枚举 `Mixed / UnifiedBand / UnifiedAttribute / UnifiedBandAttribute` mode，按该 mode 过滤卡片并解析实际技能。
3. 在每个固定 mode 内按照实际技能分桶。
4. 技能桶确定 `duration` 后，按技能时长风险窗口过滤该桶的候选谱面。
5. 固定 magazine；将乐队道具与属性道具视为参考算法中的行、列查询。
6. 不再枚举并保存全部五卡队伍和全部综合力；在技能桶内建立二元组记录，并枚举三元组，通过 2+3 MITM 直接查询目标综合力区间。
7. 命中时恢复具体五卡见证、区域道具和歌曲。

签名解析后，技能桶只比较：

```text
SkillBucketKey
  duration
  score_up
  rateup
```

`card_id` 不参与技能相等判断。浮点字段转换为固定精度整数后再作为分桶键。

MITM 中的“不重复”按角色而不是卡片下标判断：五张卡必须来自五个不同角色。二元组、三元组在构造时先排除内部角色重复，合并时再要求两侧角色集合不相交。

MITM 不负责选择或枚举 mode，也不允许跨 mode 合并。外层固定 mode 后，MITM 只负责该 mode 下的卡片与区域道具查询。为了使四个 mode 保持当前实现中的互斥语义，状态仍需保存最小的 mode 内合法性摘要：

- `Mixed`：最终乐队与属性都必须混合；
- `UnifiedBand`：乐队固定，最终属性必须混合；
- `UnifiedAttribute`：属性固定，最终乐队必须混合；
- `UnifiedBandAttribute`：乐队和属性均固定。

这些摘要只用于复核当前固定 mode，不用于在 MITM 中推导 mode。`UnifiedBandAttribute` 无需摘要；其他 mode 只携带尚未由卡片预过滤保证的混合维度。

区域道具映射：

- magazine 在外层独立枚举，并先计入每张卡的基础整数综合力；
- 普通单目标乐队道具作为行查询；
- 普通单目标属性道具作为列查询；
- 全员或多目标道具不满足“只修改一行/列”的局部性，初版单独执行完整查询；
- 卡片位于乐队与属性交叉位置时，沿用项目当前的参数分量加法和逐卡取整规则，不照搬参考文档默认的行列倍率连乘公式。

## 5. 候选歌曲

初版候选范围：

1. 仅使用玩家当前服务器已经发布的歌曲。
2. 枚举该歌曲所有已发布且存在谱面的难度。Special（难度 `4`）若存在独立的
   `difficulty["4"].publishedAt[server]`，还必须达到该服的 Special 发布时间；字段完全
   不存在时视为随歌曲本体开放，字段存在但该服为 `null` 时视为尚未开放。
3. 按当前服务器的 `publishedAt` 与 `closedAt` 筛选：歌曲必须已经发布；只要存在真实的
   限时 `closedAt` 就直接排除，不等待关闭时间到达。Bestdori 为常驻歌曲统一填入
   2099–2100 年的关闭哨兵，该值不视为真实关闭期限。
4. 原先列出的 `528`、`486`、`487`、`596`、`597`、`598`、`10003` 均由真实
   `closedAt` 稳定排除，不再维护歌曲 ID 黑名单。
5. 完成技能分桶后，对每个 `(song_id, difficulty, duration)` 执行技能尾部风险筛选。使用与精确计分相同的技能事件队列求每次技能的实际生效起点 `start_time`；若存在任一计分键（包括技能键）满足：

   ```text
   start_time + duration + 1/120
     <= note_time
     <= start_time + duration + 1/30
   ```

   则当前技能桶排除该谱面。边界按闭区间处理，并使用计分器现有 `EPS` 向两侧保守扩张，避免时间换算和浮点比较把风险键漏掉。该筛选只依赖歌曲难度和技能持续时间，不依赖 score_up、rateup、mode 或区域道具。实现将六个技能节点位置、激活/未激活计分键数量和风险标志保存在 `(song_key, duration_millis)` 模板中，同一持续时间下的不同 score_up、rate-up 和 mode 直接复用。

每个 `(song_id, difficulty)` 在固定技能桶内对应一个单调不减真实函数：

```text
f_song(stat) = Auto 精确得分
```

并满足活动基础 PT 形式：

```text
q_song(stat) = fixed + floor(f_song(stat) / divisor)
```

搜索不再先生成综合力候选。对目标基础 PT 候选 `q`，直接利用 `f_song` 的单调性反求综合力闭区间：

```text
L(song, q) = min stat，使 q_song(stat) >= q
R(song, q) = min stat，使 q_song(stat) >= q + 1，再减 1
```

缓存键为 `(skill_bucket, song_key, threshold)` 或 `(skill_bucket, song_key, q)`。

score-range 不直接使用当前锚点附近最小二乘拟合的 `ApproxScoreModel` 证明误差。改为按 Auto 的精确技能时间线，为每个键预先得到与综合力无关的基础系数 `a_i` 和技能倍率 `m_i`：

```text
exact_i(stat) = floor(floor(stat × a_i) × m_i)
meta(stat)     = stat × Σ(a_i × m_i)
```

变量定义：

- `i`：谱面中一个实际产生得分的键，`N` 为计分键总数；
- `stat`：区域道具和活动综合力处理完成后，五卡逐卡取整再求和得到的整数综合力；
- `a_i`：Auto 规则下第 `i` 个键每一点综合力对应的基础得分系数；当前 Auto 无 Combo，因此同一谱面的 `a_i` 实际相同，但仍按键表示以保留扩展性；
- `m_i`：该键计分瞬间已经生效的技能倍率，无技能时为 `1`，普通 Score-up 为 `1 + score_up`，Rate-up 使用该键对应的增长后倍率；
- `exact_i(stat)`：第 `i` 个键按两层取整得到的真实整数得分；
- `f_song(stat)`：所有 `exact_i(stat)` 的和，即歌曲 Auto 精确得分；
- `meta(stat)`：保持相同技能时间线、只移除逐键取整后的解析得分；
- `E`：对固定 `(skill_bucket, song_key)` 全综合力域成立的原始得分误差上界，单位是“分”，不随 `stat`、PT 加成或区域道具变化。

对非负倍率有：

```text
0 <= stat × a_i × m_i - exact_i(stat) < m_i + 1
```

因此可以用按倍率加权的取整次数构造严格全域界：

```text
E = ceil(Σ(m_i + 1)) + numeric_guard
meta(stat) - E < f_song(stat) <= meta(stat)
```

当 `m_i = 1` 时外层取整冗余，单键界可从 `m_i + 1` 收紧为 `1`；当 `m_i` 是其他整数时可收紧为 `m_i`。因此当前技能最大倍率 `m_i = 2.7` 时，收紧后的构造界满足：

```text
N <= E <= ceil(3.7 × N) + numeric_guard
```

完整谱面镜像当前共有 3365 张谱面，计分键数 `N` 为 `55..2331`，中位数为 `384`，P90 为 `791`，P99 为 `1112`。忽略实现层浮点保护量时，全镜像最保守上界为：

```text
E <= ceil(3.7 × 2331) = 8625 分
```

它小于现有活动公式中的最小得分除数 `9750`，所以在当前数据和技能倍率范围内，Meta 对 `floor(score / divisor)` 最多产生一个整数档的不确定性。该结论是运行时优化，不代替精确正向复核；若以后出现更长谱面或更高倍率，应按实际 `N/m_i` 重算，不能硬编码 `8625`。

`numeric_guard` 必须通过定点/有理数计算或有向舍入覆盖浮点求和误差。令整数实现使用的界为 `E_int`，则精确得分候选范围为：

```text
floor(meta(stat) - E_int) + 1 <= f_song(stat) <= floor(meta(stat))
```

### 5.1 Auto 下的收紧与精确压缩

上述 `O(N)` 误差界是适用于一般逐键线性模型的回退。当前 score-range 的 Auto 规则没有 Combo 加成，因此同一谱面的所有计分键具有相同基础系数 `a`。先精确计算第一次取整：

```text
b(stat) = floor(stat × a)
```

再只近似技能增量：

```text
skill_meta(stat)
  = N × b(stat) + Σ_active b(stat) × (m_i - 1)
```

此时无技能键完全没有误差；技能键只剩外层取整的小数部分：

```text
0 <= skill_meta(stat) - f_song(stat) < K_non_integer
```

`K_non_integer` 是技能覆盖区间中 `m_i` 非整数的计分键数量，所以误差已经缩小到技能段计分键数的数量级；整数倍率技能键也不产生误差。

初版推荐继续消除这部分误差。预处理精确技能时间线后，按倍率 `m` 对计分键计数：

```text
MultiplierGroup
  multiplier = m
  count      = 使用该倍率计分的键数

f_song(stat) = Σ_group count × floor(b(stat) × multiplier)
```

该式与当前 Auto 精确计分逐键公式等价，但一次求值只需遍历不同倍率组：普通 Score-up 通常只有无技能/有技能两个组；Rate-up 的组数等于实际出现的增长档位数，仍远小于总键数。使用与当前精确计分相同的乘法和取整语义即可复现现有结果，最终得分误差为 `E = 0`。

因此选定实现为：

1. 解析一次技能触发时间线并生成倍率分组；
2. 使用分组公式作为精确单调函数；
3. 对目标得分边界直接整数二分，不再依赖 Meta 误差扩张；
4. 解析 Meta 和 `E` 的推导保留在本文档中，不进入当前仅支持 Auto 的生产路径；倍率分组函数通过单元测试与逐键精确路径对拍。

在未来非 Auto 规则的通用回退路径中，上一节的误差界用于构造不会漏解的候选区间，再调用精确函数收紧端点。当前拟合模型及其常数 `c` 仍只可作为搜索锚点，不参与正确性证明。

同一歌曲的不同难度是不同真实函数。

## 6. 单人 PT 模型

记：

- `S`：本局 Auto 精确得分；
- `B`：活动 PT 加成倍率；
- `F`：火倍率，取 `1/5/10/15`；
- `U`：Mission Live 的支援乐队 PT 加成，由用户输入，语义为已经向下取整的 `floor(支援队伍综合力 / 3000)`；
- `floor(x)`：向下取整。

所有公式按原有层级逐层向下取整，使用整数或有理数实现，避免浮点边界误差。

### 6.1 Mission Live

其他人得分固定为 `0`。支援乐队加成不参与活动倍率，先加入一倍火基础 PT，再统一乘火倍率：

```text
PT = (floor((120 + floor(S / 15000)) × B) + U) × F
```

请求增加可选字段 `mission_support_pt_bonus`；`mission_live` 请求必须提供非负整数，其他活动忽略该字段。初版让用户直接输入 `U`，不在 score-range 内准备或枚举支援队伍。

### 6.2 Live Try

其他人得分固定为 `0`：

```text
PT = floor((130 + floor(S / 26000)) × B) × F
```

### 6.3 Challenge

只使用协力部分，其他人得分固定为 `0`，不处理挑战（歌榜）/CP 部分：

```text
PT = floor((70 + floor(S / 50000)) × B) × F
```

### 6.4 Versus

个人排名相关项置零后，单人基础 PT 仍包含固定底分 `100`：

```text
PT = (100 + floor(S / 9750)) × F
```

### 6.5 Festival

使用表格中的 5V5 单人公式，胜负项和队内排名项不进入单人计算，固定底分为 `80`：

```text
PT = (80 + floor(S / 14000)) × F
```

### 6.6 Medley

只演奏第一首歌曲后结束，因此使用完成一曲的底分 `30`：

```text
PT = (30 + floor(first_song_score / 18500)) × boost_multiplier
```

第一曲结束时，火倍率与单曲相同，直接映射为 `1/5/10/15`。

### 6.7 玩法模式边界

工作簿同时给出了 CP 挑战、竞演多人、5V5 多人、组曲二曲和组曲三曲公式。本次不增加活动子模式字段，继续使用此前确认的单人可控路径：

- `challenge` 使用 CP 协力单人公式，不使用 `3250 + floor(S/450)` 的 CP 挑战公式；
- `versus` 使用固定底分 `100` 的单人公式，不枚举多人排名分；
- `festival` 使用固定底分 `80` 的 5V5 单人公式，不枚举胜负分和队内排名分；
- `medley` 只完成第一曲后结束，不使用二曲/三曲底分和多曲火倍率之和。

若以后要支持这些玩法，必须在请求中新增显式子模式，不能只根据 `EventType` 猜测。

### 6.8 得分区间

PT 公式含有多层 `floor`，同一个目标 PT 对应一个或多个闭区间得分范围。实现流程先生成
可能的得分区间，再用倍率分组后的歌曲精确单调函数反解综合力区间，最后以前向精确 PT 计算复核。

## 7. 演奏动作

请求输入包含 `current_pt` 和 `target_total_pt`，搜索目标为：

```text
target_delta_pt = target_total_pt - current_pt
```

若目标总 PT 小于当前 PT，则请求无解。

令某支队伍、某套区域道具和某首歌曲的一倍火基础 PT 为 `z`。因为允许一倍火，重复同一歌曲恰好达到目标的充要条件为：

```text
z > 0 且 target_delta_pt % z == 0
```

因此只需枚举 `target_delta_pt` 的正因数作为 `z` 候选。命中后令：

```text
units = target_delta_pt / z
```

再使用 `15/10/5/1` 将 `units` 分解为最少演奏次数。歌曲种类的唯一键为 `(song_id, difficulty)`。

## 8. 单阶段因数区间 + 2+3 MITM

这里只保留原阶段 A。输入映射到参考文档：

```text
参考物品 t        = 技能桶中的卡片
物品唯一性        = character_id 不重复
离散属性 p_t      = 单卡活动 PT 加成的定点整数；无 PT 倍率活动恒为 0
属性 a_t          = 固定 magazine 后、应用某行列道具查询时的单卡整数综合力
真实函数 f_l      = 某 (song_id, difficulty) 在当前技能桶下的 Auto 精确得分函数
目标 y            = target_delta_pt
行 / 列           = 单目标乐队道具 / 单目标属性道具
```

### 8.1 从目标因数生成综合力区间

枚举 `y` 的全部正因数 `z`。对无 PT 加成倍率的活动，`z` 直接确定 `q=z`。对 `live_try/challenge`，固定五卡 PT 加成总和 `P` 后，求满足下式的整数 `q`：

```text
z = floor(q × (BASE + P) / BASE)
```

其中 `q` 已包含对应活动固定底分。对 `mission_live` 还要固定用户输入的支援加成 `U`，先求：

```text
z - U = floor(q × (BASE + P) / BASE)
```

只有 `z > U` 时才可能命中，再按同一整数反解逻辑求 `q`。

使用统一定点基数 `BASE`，通过整数 `ceil_div` 求至多一个候选 `q` 并正向复核。再对每首歌把 `q` 反解为精确综合力区间 `[L, R]`。

对每个 `P`，合并所有歌曲和所有因数产生的综合力区间，形成：

```text
ValidIntervals[P]
```

MITM 只需判断五卡综合力是否落入对应 `P` 的任一有效区间。

### 8.2 二元组预处理

对技能桶内所有角色不同的卡片二元组 `(u,v)`，记录：

```text
PairRecord
  point_bonus_sum
  stat_sum
  card_u, card_v
  character_mask / character_ids
  mode_local_signature
```

`(P, stat)` 使用分段键或二级索引排序。查询时必须支持：

- 综合力落入一组闭区间；
- 二元组角色与给定三元组不相交；
- 二元组与三元组合并后满足当前固定 mode 的剩余合法性约束。

基础正确版可以在命中区间内扫描并检查；高性能版再按参考文档实现角色 incident 计数、固定 mode 内的摘要分片和区间存在性查询。

### 8.3 三元组枚举与见证恢复

枚举内部角色互异的三元组 `(x,y,z)`，计算其 `(P_3, stat_3)` 与当前 mode 所需的最小摘要。对每个目标区间 `[L,R]` 查询二元组：

```text
P_2 = P_target - P_3
stat_2 ∈ [L - stat_3, R - stat_3]
```

找到角色不相交且满足固定 mode 剩余约束的二元组后，立即得到五卡见证。最后使用真实歌曲函数和 PT 公式正向复核。

### 8.4 区域道具批查询

固定 magazine 后，在乐队道具和属性道具中选择类别数较少的一维作为外层。对每个外层道具构造基础二元组集合；内层道具只增量替换接触该目标类别的二元组与三元组贡献。

基础状态有解时，见证最多接触五个内层类别，未接触的内层道具可直接复用该见证；基础状态无解时，只枚举至少接触当前内层类别的三元组。全员/多目标道具走独立完整查询，不使用该局部性推导。

### 8.5 返回

每个命中记录至少包含：

```text
五张卡
区域道具
歌曲与难度
一倍火基础 PT z
15/10/5/1 的最少局数分配
精确得分
```

目标 PT 的一倍火 PT 因数按 `(最少局数, 实际总火耗)` 分层。低于玩家数据导出的全局保守 PT 下界
（该下界不低于 `score = 0` 的理论底分）或高于全局乐观 PT 上界的层直接排除；首个有解层即为
全局最优层。其余层依次使用 mode 粗界、技能桶粗界和持续时间模板界排除。搜索在该层收集到
`max_results` 个有效见证后可以提前结束，若最优层不足 `max_results` 个结果，不使用较差层补足。
每个返回结果都必须通过精确得分和 PT 公式正向复核；单曲查询无解时直接返回空结果。

## 9. 已确认语义

### 已确认并沿用

- 输入目标为 `当前 PT + 目标总 PT`，内部搜索 `target_delta_pt`。
- 只保留一种 `(song_id, difficulty)` 重复演奏的方案；无解时直接返回空结果，不再进入两曲或完全背包。
- 同曲不同难度视为不同歌曲。
- 五张卡必须是五个不同角色，且技能完全一致；仍按四类 mode 签名约束队伍。
- 同一方案的每局可以选择不同火倍率。因为一倍火存在，先判断一倍火基础 PT 是否整除目标，再用 `15/10/5/1` 分解最少局数。
- 每个方案使用 `15/10/5/1` 得到该一倍火单位数下的最少局数，并按 `1/5/10/15 -> 0/1/2/3` 计算实际火耗；不同队伍、歌曲和道具方案之间按 `(演奏次数, 实际总火耗)` 做严格全局词典序优化。
- PT 加成以单卡原始微单位保存，二元组和三元组只做整数求和；五卡合计后统一取整到 basis point 一次，中间结果不得分别取整。
- 区域道具综合力完全沿用当前 `PreparedCard::add_up_stat`：基础、活动、乐队、属性、magazine 分量相加后逐卡取整，不采用参考文档的行列交点倍率连乘。
- mode 在 MITM 外层枚举；MITM 只处理固定 mode、固定技能桶下的卡片和道具查询，不在二元组与三元组合并时选择 mode。
- score-range 的 Auto 路径按精确技能时间线聚合倍率组，以压缩公式直接计算精确得分，误差 `E = 0`；解析 Meta 与加权取整误差界只保留为设计推导。
- 技能分桶后按 `(song_key, duration)` 检查尾部风险窗口；只要 `[duration + 1/120, duration + 1/30]` 内出现计分键，该技能桶就排除对应谱面。
- Auto 基础倍率由目标 PT 请求在 `0.5/0.75` 中选择；未指定时日服默认 `0.75`，其他服务器默认 `0.5`。所选倍率必须贯穿歌曲初始化、倍率分组、精确计分和缓存键。
- score-range 支持六类活动；`festival` 使用 5V5 单人 `80 + floor(S/14000)` 公式，`mission_live` 使用用户输入的支援 PT 加成。`maximize` 的支持范围保持不变。
- 歌曲候选继续使用“服务器已发布、对应难度已发布、任一 `closedAt` 进入黑名单”的现有过滤规则。

### 实现默认值

1. **全员与多目标道具。** 当前数据除全员道具外没有多目标道具。单目标乐队/属性道具进入行列增量查询；全员道具走独立完整查询，不参与局部复用。未来若出现多目标道具，同样走独立完整查询。
2. **magazine 维度。** 完整枚举玩家当前拥有的 performance/technique/visual magazine，每套 magazine 作为独立固定查询上下文。
3. **综合力反解定义域。** 初版使用覆盖当前技能桶全部道具上下文的全局可行综合力上下界，以复用 `(skill_bucket, song_key, q)` 反解缓存；若基准显示区间过宽，再改为上下文局部界。
4. **结果数量与顺序。** 返回数量沿用请求的 `max_results`，默认 `20`。只返回首个全局最优 `(演奏次数, 实际总火耗)` 层中的任意见证，达到上限后提前结束；最优层不足上限时不返回较差方案。同一内部状态继续只保存 canonical solution。
5. **非标准技能键谱面。** 完整镜像中仅 `786/special` 含 17 个技能键；该歌曲存在真实 `closedAt`，按既定歌曲过滤规则进入黑名单。进入候选集的谱面仍在准备阶段校验恰好 6 个技能键，异常时跳过并记录原因。

当前已无影响核心正确性的待确认语义；以上默认值只在基准测试或输出需求变化时调整。
