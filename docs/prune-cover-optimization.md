# 替换覆盖剪枝优化（2026-09-16）

本轮优化同一组剪枝条件的计算成本。没有增加删除卡牌的规则，没有缩小候选集合，也没有修改综合力上界、18500 分带、技能概率或三队搜索。

## 完整档案对照

原生 Release，Ryzen 5 5500U，单线程搜索。两份档案分别在同一个可执行文件内切换 `BANGDREAM_OPTIMIZE_COVER_PRUNE=off/on`；两侧都启用上一轮相同倍率压缩评分、AVX2 第二层过滤和第三层前缀复用，关闭倒排位图实验。

每种情况跑一次，无额外预热。执行顺序为 1456 卡关闭 → 开启，1414 卡开启 → 关闭。编译与测试不与计时运行并行。

## 原逻辑与改动

跨角色替换检查需要确认：在最不利的四名队友与另外两支队伍占用卡牌后，还剩多少张可替换卡。原实现为每首目标歌分别执行一个动态规划，状态包括四名队友的占用数、另外两队各五个位置的占用数，以及是否打破同乐队／同属性。

1. **只记录当前签名需要的区别。** 同乐队同属性无需区别状态，只有同乐队或只有同属性需要一位，既不全队同乐队、也不全队同属性时需要两位。三队的状态数组从统一 720 项变成 180 / 360 / 720 项；单队没有另外两队的占用，缩为 5 / 10 / 20 项。
2. **复用相同的歌曲条件。** 各角色在两首其他歌上的可占用组合完全一致时复用结果；交换两首歌后相同也能复用，因为每首歌的容量都是五个位置。
3. **已得到零覆盖即可结束。** 最终取所有目标歌覆盖数的最小值，而覆盖数非负，因此遇到零时不再计算后续歌曲。
4. **去掉重复检查。** 硬支配图与综合支配图对当前卡的替换集合相同时，覆盖结果相同，直接复用。
5. **缩短内部循环。** 仅遍历当前处理的角色可能到达的队友／占用范围；不重复执行“什么也不占用”的转移。查询某卡是否为替换卡改为一次建立标记表；另外两队能否各占一张卡改为线性计数。

两队同时占用必须使用不同卡。判定条件是两边分别有可用卡且二者并集至少两张；一张对两首歌曲都可用的卡不会被当作两张。

投影掉不需要的区别位，不改变其余状态的最优值；所有计数仍采用整数。除了一次调用内的复用，没有跨档案或跨道具的持久缓存。

## 验证

- 新增 2,048 组随机比较，覆盖全部四种签名、1 / 3 队及 0..7 歌曲可用掩码；另有 4,096 组不同卡片占用与不可满足签名条件的边界比较，覆盖数量逐项等于旧完整 DP。
- 全部 core 测试：180 项通过、1 项原有随机压力测试跳过。
- 1456 卡：38 批共 5,860,064 条原始候选；1414 卡：21 批共 3,693,336 条。完整原始候选索引、三曲分数、队长、技能顺序及综合力的逐批指纹全部一致。
- 所有非计时结果字段、保留候选数量、成队结果和逻辑搜索计数与同轮关闭模式以及上一轮冻结结果一致。
- WASM core 编译通过，保留 4 条 solver 与 3 条 core 的既有未使用代码警告。本轮是原生 Rust 性能结果，未测浏览器 WASM 性能。

首次带完整调试信息的测试编译遇到 LLVM 内存不足；关闭测试构建调试信息与增量编译后通过。没有改动用户其他进程或系统配置。

## 剩余开销

优化后覆盖检查约占剪枝总耗时的 16%。新档案贡献模型上下文约 0.833 s，上界初始化约 0.977 s；旧档案分别约 0.555 s、0.586 s。后续可以继续研究这些上下文的重复构建；如果要增强剪枝强度、进一步减少候选，则需要另行证明替换与上界条件，不应把本轮节省的计算等同于删掉更多候选。
