# 推荐编队与技能触发顺序

推荐编队按游戏显示槽位从左到右排列，第三位为队长。技能触发顺序是另一组排列：前五次各使用一名成员的技能，第六次使用队长技能。

## 概率表

依据国服 9.4.2 ARM32 客户端的分析：从 `[0,1,2,3,4]` 开始，依次取出当前列表下标 `i` 的成员，插入随机位置 `0..3`，重复五次。共有 `4^5 = 1024` 条等概率路径，对应 96 种可达排列；另外 24 种排列权重为零。

生产代码直接使用 `crates/core/src/skill_shuffle_weights.rs` 中的 96 项整数权重，每项概率为 `count / 1024`。启动后一次性建立站位到技能顺序的映射，计算期间不做随机模拟或 1024 路径枚举。测试独立枚举原算法，并对照原始概率表校验全部 120 种排列。

该证据来自国服上述版本，未据此声称所有服务器与版本都已验证。五名玩家的协力技能顺序继续使用原有独立模型，不套用此表。

## 计算规则

- 最高得分：保留最高分选队与队长，在其余成员的 24 种站位中，优先最大化所有达到最高分顺序的合计概率；其次比较单一最优顺序的概率、平均分数，最后以卡牌 ID 稳定打破同分。展示推荐站位，以及其中概率最高的一种最优技能顺序（使用上方卡位 1–5 的序号，以箭头连接；第六次标明队长）。页面只显示所有可达最高分顺序的合计概率，使用最简分数；示例技能顺序不单独标注概率。“顺序与概率说明”在歌曲与队伍区域仅保留一处外链，直接指向用户指定的 HHWX 评论。
- 平均 PT：在选队搜索过程中比较全部 120 种站位（包括队长选择）。每条技能顺序先计算真实整数分数及 PT，再按权重求期望；不以平均分数代入 PT 公式。平均 PT 同分时优先平均分数。
- 巡回平均 PT：三曲独立洗牌，联合优化三支队伍及其站位，精确处理三曲合计分数的 PT 取整。仅可使用逐分布的随机占优关系排除站位，不能只保留每曲平均分数最高的站位。均值仅用于可证明安全的搜索上界。
- 指定队伍：直接按用户提供的槽位计算加权分布，不自动重排卡位。
- 重叠技能：保留严格计分回退；无重叠时复用增量矩阵。

## 数据兼容

最高分结果新增可选 `songs[].teamOrder`，包含 `recommendedTeamCardIds`、`skillOrderCardIds`、单序列与最高分合计路径数、最高分顺序种数及总路径数。

平均 PT 单曲结果在 `team.evaluation.recommendedTeamCardIds` 提供站位；巡回结果在 `medley.teams[].recommendedTeamCardIds` 提供。指定队伍不输出自动推荐字段。旧结果缺少这些字段时不推测推荐站位或概率，提示重新计算；新计算使用新的模型缓存键。

`scoreDistribution.entries` 中的次数是权重，不代表不同顺序数量。单曲样本权重和为 1024，巡回三曲联合为 `1024^3`；协力沿用原模型分母。

## 验证记录（2026-09-15）

- 原始 1024 路径与固定 96 项权重逐项一致；线性均值上界与全排列对照一致。
- 原生路径穷举验证单曲 PT 的推荐站位与概率加权，三曲加权分数逐项验证联合 PT 取整；指定卡位和重叠技能分别回归。
- 浏览器真实 15 卡三曲样本展示、1440px / 390px 布局、非零突破徽标、六次触发顺序，以及结果图片导出均已检查。
- 本机浏览器 2,147 卡巡回平均 PT 样本计算约 12.2 秒（含完整选队与道具搜索）；仅是该档案、谱面与机器的测量，不作为统一耗时承诺。
- Workspace 编译检查及 WebAssembly release 构建通过；data / service / web-wasm 接入测试通过。
