## 漏检与原因

用户截图指出导入目标前的国服图标撑大弹窗。上一轮记录的 97 项前端测试、16 项服务端测试主要覆盖逻辑；浏览器检查读取了文本树、切换来源并验证缺失 ID 提示，没有截图检查实际图形尺寸，不能据此声明视觉验收完成。

设计稿的 `flagInline` 带有 17×13 的尺寸与行内对齐。正式接入将它合并为通用 `flag`，图片失去尺寸，页面的 `img { display:block }` 规则进一步使图标单独占行。本轮修复前在真实预览复现，目标图标约为 547×547。

## 修复

- 为普通服务器图标恢复 24×19 的 HTML 尺寸属性，选择器和摘要区域继续使用原设计的具体尺寸。

用户当前活动 #336 实际处于 `fallback`，错误为图片只可显示、不能读取像素。预览日志明确为进程出站连接被拒绝（WinError 10013），导致 `/bestdori/header/` 返回 502。原因是本轮重启开发服务时没有使用获准的联网执行环境；这不是纹理算法参数变化，前两轮下拉框检查也没有覆盖纹理生成。

先在独立 8094 服务恢复联网，确认 #336 生成 2880×272 补全图，再替换 8093 服务并刷新用户原页面。实际 8093 中 #336 为 `ready`，卡牌背景和日服前景代理返回 200；国服尚无对应前景时仍按原规则回退日服。没有改动原采样、拼接、模糊和前后景几何。

恢复像素读取后还发现阴影克隆的 Blob URL 已被释放，导致阴影自然尺寸为零。现将原始素材 URL 保留到活动场景替换时再释放；过期异步加载也会释放。浏览器确认 #336 前景和阴影均为 1024×1024，前景有效边界可读取，修改的 JS 语法检查通过。
