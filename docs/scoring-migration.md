# 原生算术迁移验收

日期：2026-09-20。计分规则标识：`cn-9.4.4-f32-v1`。这是计分算术迁移，不是击打时机优化上线。

## 正式调用路径

指定队伍、单曲及巡回最高分、最大平均 PT、协力、Auto、控分均从正式数据准备取得成员逐维原生运算数。计分传递非负有限 `ScoringPower`；整数综合力只用于显示或原有房间门槛。网页 WASM、桌面端和服务端调用同一 core。

- `PreparedCard.native_power` 保存养成后的整数三维、原生活动百分点及额外轴加成。养成自身的取整规则保持原模型。
- 道具主数据同时保留原始百分点，按选中道具的数值 ID 累加后除以 100。旧档案不包含游戏内道具放置遍历顺序，不能声称复原了每台设备的顺序；这属于输入资料限制。
- 成员三维依实际物理位置累加，然后按 `T + (P + V)` 得到计分综合力。队伍显示走原始、道具增量、活动增量的独立累加路径；三队显示先合计未取整显示值，再取整一次。
- 每键依原生 f32 顺序计算基础值、判定和 Combo，第一次截断后再应用 Fever 与技能倍率并截断。递增技能使用原生百分点状态逐键推进。
- 推荐摆放和技能触发顺序分开计算。平均 PT 仍用原有 1024 条随机路径的权重；最高分命中概率合计所有达到最高分的顺序。协力保留五位玩家的原概率模型。
- 最终控分方案通过实际浮点综合力重新结算；一曲和两曲恢复路径都校验溢出。二分探测可用饱和哨兵扩大上界，哨兵不能成为实际返回的得分。

## 保留的加速与安全边界

物理摆放可能改变最后几位单精度值。先按完全相同的综合力位模式分组，再共享计算；仅当所有曲目的每类第一段整数键分在整个保守综合力区间内完全相同，才将多个位模式合并。这样后续技能、Fever、排队得到的输入整数一致。整组摆放等价时，共享只读摆放索引与可达顺序掩码，不再为每个候选重建 120 项。相同状态压缩、原生 AVX2、位图冲突、兼容队伍上界、第二队过滤和第三队前缀复用继续使用。

候选的连续三维和仅用作界限，不直接用于最终计分。非负浮点累加以 `gamma(6)` 向外包围；连续分数上界使用覆盖综合力与后续评分运算的 `gamma(32)`，再覆盖 f64 界限计算误差。贡献替换的预算包含第一、第二段截断及两侧浮点误差。技能内键数使用实际触发位置与最长时长时间线包围：从立即触发的最早起点至最长时长产生的最晚结束，覆盖无延后、单次延后和连锁；每键分别使用实际 Fever 倍率。无排队、单次延后和连锁状态均沿用已经证明覆盖的时间线范围。

硬支配优先检查逐维综合力；逐维不占优时，仅当标量优势超过整个候选池中两支队伍的浮点累加误差之和，才允许标量支配。近似同分仍保留；相同标量但不同运算数不互相合并。协力填充 DP 在最优标量附近保留舍入误差范围内的候选；缓存保留所有成员运算数。最低综合力检查最终推荐摆放的显示值。

控分逆像使用有序 f32 位模式，区间前驱/后继是一 ULP。二卡/三卡 MITM 仍按线性和检索，但范围向外扩大以覆盖逐维原生累加；叶子恢复实际五人摆放后重新结算。

## 历史与诊断

新结果携带引擎输出的规则标识，缓存键升级为 schema 9；schema 7、8 历史继续读取、保留原分数和原标识，只禁止用于新计算命中。资源刷新不删除历史。旧 WASM 缺少标识时不会由前端代填当前标识。

`score_check` 根据诊断中保存的推荐摆放和技能顺序回放，使用新浮点计分与三队显示规则。缺少摆放/技能顺序的旧诊断需重新计算；原历史记录不因此修改。

## 保留的模型边界

本次保留既有同刻节点调度、技能延后策略和巡回 Combo 表，不将时机假设变化混入算术分差。Great、判定修正技能、显式击打位置和 60/120 FPS 联合搜索仍属于后续击打优化阶段。

多人协力按显示综合力选择第六技能时，跨过队友综合力会改变重复的队长技能；原有“填充卡取最大综合力”模型不具备对这种切换的全局最优证明。本轮迁移其算术与浮点近邻保留，不把既有搜索假设扩大表述为所有自定义协力输入下的最优性证明。

## 复现

```powershell
cargo test --offline --release -p bangdream-optimize-core -p bangdream-optimize-data -p bangdream-optimize-medley-solver -p bangdream-optimize-web-wasm --lib
cargo check --offline --workspace --all-targets
node --test apps/web/test/*.test.js
python -X utf8 -B scripts/test-prepare-web-release.py
cargo build --offline --release --manifest-path scripts/research/native-score-probe/Cargo.toml --target-dir target/native-score-audit --bins
```

完整输入和输出位于忽略的 `tmp/native-migration/`，不提交玩家档案。`search.exe <max|pt|evaluate|control> <input.json> <output.json>` 调用正式入口；旧诊断 fixture 使用完整 filesystem 主数据。跨平台检查脚本为该目录的 `parity.cjs`，阶段基准为 `run-benchmark.py`。独立原生复核使用 `scripts/research/verify_native_scoring_integration.py`，需要原生 ELF 及本地逆向辅助模块。
