# 候选技能初始顺序复用（2026-09-16）

本轮继续优化五卡候选枚举中的评分开销。保留上一轮的兼容性与两队合计上界剪枝，并在每个签名池内复用不依赖综合力的技能初始顺序。最终整数分数和最优技能顺序仍逐队计算，没有改变概率、剪枝门槛或搜索范围。

- 1456 卡：国服活动 323，活动歌曲依次为 186 SP / 395 SP / 772 EX。
- 1414 卡：历史基准档案，自定义活动 0，306 EX 三曲。

## 实现与正确性

原流程为每支候选、每首曲子执行两次顺序计算：先按未取整的技能贡献矩阵计算初始顺序，再依据当前综合力的整数分数矩阵求最终最优顺序。前者不依赖综合力，同技能组合会反复得到相同结果。

新实现 `crates/core/src/medley/scoring/cached.rs` 在进入签名池时，为每张卡的三曲、每曲六次触发贡献建立类别编号：

1. 类别键包含全部 18 个 `f64::to_bits()`，使用精确位比较，不用误差阈值。
2. 五个类别编号按当前五卡位置组合成 80 位键。没有排序，也不将卡牌 ID 写入缓存，保留原 DP 同分时的位置选择规则。
3. 固定 32,768 个直接映射槽，槽内同时保存完整键与三曲的顺序、队长位置。哈希碰撞只会替换旧条目；完整键不等时必定重算。
4. 缓存主体约 1.5 MiB，类别编号另占少量空间。分类阶段的临时哈希表在初始化后释放，缓存本身在当前签名池结束时释放；不随枚举数量持续增长。
5. 缓存只在持有不可变卡牌、谱面和选项引用的评分器中使用，不跨签名、道具或输入复用。超过 `u16` 类别容量时回退到原计算。

缓存保存的是初始顺序，不是最终答案。每次仍按当前卡牌计算综合力，保留原来的两层取整，计算精确分数矩阵并求最优顺序；技能不同、综合力不同、卡牌身份不同的结果仍由这些计算决定。同分时所用的初始顺序也与原 DP 一致。

`candidate_profile_*` 是抽样计时。开启缓存后，缓存查询和未命中的初始顺序计算位于内部评分器之外，因此不能再从内部 `candidate_profile_seed_ms` 推算缓存总耗时；外层 `build_candidate_ms`、`enumerate_ms` 和完整计算计时覆盖这些工作。

## 未采用的整队分数缓存

本轮先试过用“五个技能类别 + 总综合力”缓存整队三曲分数、队长和顺序，使用同样固定大小的直接映射表。

虽然正确性对照通过，但两个完整档案的命中率仅 0.0228% / 0.1735%。对应整轮计算为 37.889 → 39.839 s、22.293 → 24.254 s，查询和写入开销大于收益，因此没有保留到生产代码。该轮记录在 `tmp/candidate-cache-study/`。不能把该轮的关闭时间用于上表的加速比。

- 两份档案的所有最终非指标字段完全一致，包括队伍、道具、推荐顺序、队长、分数分布、总分分子和 PT 范围。
- 所有非耗时搜索计数相同：原始候选 5,860,064 / 3,693,336，最终保留候选 78,079 / 117,831，二层与三层检查数、合法方案数和精确分布数都未改变。

- 精确平均 PT 保持 `728394032679 / 1073741824` 和 `789280615173 / 1073741824`。
- 新增三项针对测试，覆盖不同卡牌 ID、位置重排、综合力变化、技能变化、相同技能同分、贡献位变化、重叠/非重叠时间窗、单槽碰撞淘汰，以及 1,000 组随机队伍与原评分器的逐字段比较。

- core 全部测试：188 通过、0 失败，1 项原有压力测试跳过；WASM core 编译通过，保留原有 solver 的 4 条和 core 的 3 条未使用代码警告。
- `git diff --check` 通过。

本轮性能数据是平均 PT 目标的原生程序计时，没有测浏览器 WASM 或桌面 UI 的端到端时间。缓存位于共享巡回候选枚举器，最高分目标也能使用；本轮没有另跑最高分目标的完整档案计时。

## 当前完整耗时分解

开启缓存后的单轮耗时，单位为秒；各行互不重叠。

| 阶段 | 1456 卡 | 1414 卡 |
|---|---:|---:|
| 道具组合上界 | 0.924 | 0.732 |
| 原始候选构建与筛选 | 21.485 | 12.530 |
| 加权平均分转换 | 1.299 | 1.979 |
| 平均分种子搜索 | 0.194 | 0.228 |
| 三队搜索及其中的精确 PT 评价 | 9.484 | 4.746 |
| 其他未单独计时（差额） | 2.013 | 1.454 |
| 总计 | 35.398 | 21.670 |

这里的“平均分种子搜索”是候选生成后的 512 轮随机桶，和本轮缓存的“技能初始顺序”是不同步骤。最终三队分带搜索仍是 AVX2 完整扫描。其他差额包括初始方案准备/评价、平均分带筛选、掩码压缩和结果整理等。

剩余主要开销仍是原始候选精确评分与高分队伍的三队搜索。本轮减少重复计算，不减少枚举数量，也未修改最终三队搜索。
