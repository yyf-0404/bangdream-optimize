## 项目结构

计算代码按“共享数据准备 + 独立搜索策略”组织：

- `crates/core`：领域模型、共享综合力计算、最大化与控分编排、单曲精确搜索和 Medley 候选生成。
- `crates/team-prune`：单曲与 Medley 共用的支配图和分组覆盖剪枝。
- `crates/medley-solver`：候选队伍上的严格标量/AVX2 搜索和 random-bucket 回退。
- `crates/data`：Bestdori/game-data 镜像与计算快照构建。
- `crates/service`：最大化和控分应用服务。
- `crates/web-wasm`：浏览器 WASM 计算边界。
- `apps/server`：HTTP 服务。
- `apps/web`：Web 与桌面端共用界面。
- `apps/desktop`：Tauri 桌面端。
- `tools/sync-bestdori`：静态 Bestdori 镜像生成工具。

旧 Node/CPP 运行时不再是本项目的执行依赖。

## 共享准备与综合力

`prepare_event_context` 是最大化和控分共用的准备入口，统一处理：

- 玩家档案、卡片等级、突破和技能等级；
- 角色、属性和指定卡面的活动加成；
- 区域道具和 magazine；
- 活动综合力加成与活动 PT 加成的分流；
- 单卡未取整综合力和五卡统一向下取整；
- 卡片 PT 加成先求和再统一取整。

最大化和控分共用 135 套原始区域道具组合。同类型、同目标键的组件构成一组；任一组内组件在玩家档案中显式为 0 级时，该组整体不生效。59/72 互斥替代品仍选择已持有加成较高者。

## 最大化

### 单曲

生产入口位于 `crates/core/src/single.rs`，使用共享安全预剪枝后进入 `single/exact.rs` 的严格五卡搜索：

1. 按角色分组，只枚举五个不同角色。
2. 使用同形状、同角色和跨角色安全支配缩小卡池。
3. 使用综合力和连续技能 Meta 的安全上下界做分支限界。
4. 在五卡叶子枚举队长位置并执行精确整数计分。
5. 最终分数、综合力、技能顺序和队长都来自精确时间线。

`DpChartModel` 仍用于构造连续 Meta 安全界，但不决定最终分数或最终技能顺序。

2026-09-17：单曲最高分与单曲平均 PT 已接入排队状态优化。标准时长的非连锁、连锁排队恢复贡献剪枝与可达技能位上界；最高分叶子复用状态转移区间的整数贡献，PT 复用完整加权评分摘要。多人协力外部技能的排队贡献剪枝仍保守跳过。详细边界、回归和同条件内核复测见 `docs/single-queue-optimization.md`。

### Medley 候选生成

每套道具按以下签名枚举队伍：

- `Mixed`
- `UnifiedBand(band)`
- `UnifiedAttribute(attribute)`
- `UnifiedBandAttribute(band, attribute)`

每个签名池依次执行同形状初筛、全局同角色支配、全局跨角色支配和固定点收缩。贡献剪枝使用综合力区间与十个物理角色场景的连续 Meta 安全界；若无法证明严格支配则保留卡片。

形成五卡队伍后，为三首谱面分别计算精确综合力和技能顺序，再交给 `crates/medley-solver` 选择三支互斥队伍。

### 精确技能排序

最大化统一假设理想 60 FPS、无掉帧且歌曲零点与帧边界对齐。普通键与技能键同时出现时，允许普通键延后一帧点击并获得技能加成。

Medley 三类生产路径共用实际判定区间语义：无排队保留 `5 × 6` 精确整数增量矩阵；非连锁使用“技能位置、前驱卡、当前卡”的条件增量及固定状态 DP；连锁使用实际判定区间与后续等价类编译的状态图。平均 PT 保留各触发排列的独立得分和原有非均匀概率，不能用最高分路径替代整个分布。

非连锁贡献剪枝同时计入被替换卡、下一技能及队长复唱；连锁贡献剪枝推进替换前后的成对等价状态，并共享相同后续状态的差值下界。候选、道具与剩余队伍上界覆盖全部可达窗口。标准时长的连锁结果通过 `skillQueueNotices` 显示已计入排队，覆盖外输入及旧历史保留非最优警告。指定队伍固定位置和队长，直接按完整时间线穷举。详见 [技能排队支持](skill-queue-support.md) 与 [状态表优化](skill-queue-state-optimization.md)。

2026-09-17 已完成非连锁排队评分优化：条件窗口随谱面预计算，重复技能/窗口增量复用，基础分使用倍率段压缩，顺序动态规划使用紧凑路径编码。新 1,456 卡档案、8 SP / 395 SP / 772 EX，关闭详细诊断的同条件原生对照为最高分 474.858 → 50.855 秒、平均 PT 467.192 → 64.463 秒，完整业务结果、候选数及搜索计数均一致；原 186 SP 无排队输入的结果也一致。Core/Data/Service 233 项有效测试通过，全谱面 559 组非连锁配置与 335,400 次完整调度评分一致。详见 [窗口复用优化](skill-queue-window-optimization.md)。此前含全局剪枝诊断的计时，以及历史无排队输入和本次排队输入的区别，保留于 [性能回归及基线复核](skill-queue-performance.md)，不能与当前结果混算。

后续第二轮将非连锁技能排序展开为固定状态，并跳过前驱无关窗口的重复检查。相对上一轮实现，以同一排队输入交错各复测两轮，最高分核心均值 53.058 → 48.392 秒（减少 8.8%），平均 PT 67.962 → 62.821 秒（减少 7.6%）；候选评分分别由 25.491 → 20.522 秒、31.168 → 25.212 秒。八次排队输入和两个无排队完整对照均保持业务结果、候选数及搜索计数一致。详见 [第二轮固定状态优化](skill-queue-fixed-state-optimization.md)。

三曲排队压力测试已补充：同一 1,456 卡档案、活动 323，改用 8 SP / 66 SP / 59 SP，三首在 7 / 7.5 / 8 秒上限均为非连锁。各目标各版一轮原生 Release：最高分 82.125 → 68.957 秒，平均 PT 133.952 → 114.295 秒；完整结果和搜索计数一致，两项 WASM 15 卡回归也通过。三首推荐队伍的可达顺序均有排队，但 66 SP 展示的最高分顺序恰好避开排队。详见 [三曲排队测试](skill-queue-three-song-benchmark.md)。

### Solver 选择

- `StrictExact`：严格全局搜索，优先 AVX2，不可用时使用标量。
- `FastApproximate`：直接使用 random-bucket，并把结果标记为 `approximate`。
- `Auto`：候选数不超过 196,608 时使用 exact，否则使用 random-bucket。

候选数只是保守分流条件；exact 的实际成本主要由冲突结构和动态剪枝决定。

## Score range

控分流程位于 `crates/core/src/score_range`，与最大化并列维护活动支持范围和计分规则。

当前约束：

- 整个方案使用同一支队伍；
- 单曲与两种不同 `(song_id, difficulty)` 的方案共同按 `(演奏次数, 总火耗)` 全局优化，不同难度视为不同歌曲；同一最优层先查单曲并允许命中后直接返回；
- 每局可独立选择 `1/5/10/15` 倍火；
- 全局先最小化演奏次数，再最小化实际火耗；
- 二曲仍无解时返回无解，不继续运行完全背包。

队伍与道具搜索使用：

```text
统一的单曲因数 / 二曲 PT 对目标层 → mode → 技能桶 → 道具上下文 → 惰性 PT/得分反解区间 → 2+3 MITM 行列批查询
```

MITM 索引使用 `floor(Σ 单卡未取整综合力)` 的真实综合力公式，并保存 canonical 见证。二曲阶段只
补齐当前目标层实际使用的单局 PT；跨层相邻边界按“目标分数 → 全歌曲综合力下界列”紧凑缓存。

### Auto 计分与 PT

- 日服 Auto 基础倍率为 `0.75`，其他服务器默认为 `0.5`，请求可显式选择。
- 无 Combo 加成。
- Rate-up 仍按经过键数逐键增长。
- 同时出现的普通键在技能键之前结算，因此不获得刚触发技能的加成。
- `mission_live` 的支援队伍 PT 加成由用户输入。
- `challenge`、`live_try` 和 `mission_live` 的活动加成进入 PT 倍率，不直接进入综合力。

### 谱面模板与过滤

前后端统一使用 `api/scoreRangeChartMeta.2.json`。歌曲与难度分别作为候选，并应用以下过滤：

- 目标服务器已发布歌曲；
- 难度及 Special 发布时间已到；
- 任一 `closedAt` 存在则进入黑名单；
- 必须恰好有六个技能键；
- 技能结束和排队风险按 60/120 FPS 包络筛除。

本地完整镜像由 4,167 份谱面生成 3,364 个安全歌曲/难度候选。实际 CDN/静态服务器发布仍属于仓库外部署步骤。

## 历史实验结论

以下方案曾实现或测量，但收益不足、复杂度不合适或已被更严格的算法替代：

- 单曲 `Sa × (D + Sb) + C` 近似 DP：无法满足严格全局精确要求，相关独立 crate 已删除。
- score-range 完全背包和三阶段综合力 DP：与当前最多使用两种歌曲的产品约束不一致，已删除。
- 旧 score-range 两曲规划曾直接展开歌曲组合并与三阶段综合力 DP 结合，成本过高，已由“单局 PT 方程 + 单 PT 综合力区间缓存 + 区间交集”替代。
- score-range NTT/快速卷积和延迟恢复：在改用目标因数区间与 MITM 后不再需要，已删除。
- Medley Meta 最终计分、延迟精确化和按需技能格：完整 `5 × 6` 精确矩阵更简单稳定，旧路径已删除。
- Top-2 分配证书和有界 exact 探测：附加成本超过剪枝收益，未进入生产。
- 按谱面拆分共享卡池：模拟收益不足，已撤回。

## 已知风险与下一步

1. Medley 无排队、非连锁与连锁共用实际判定区间语义；连锁已接入后续等价状态、成对状态贡献下界及可达窗口上界。标准离散时长的六技能点输入不再因连锁本身提示非最优，覆盖外输入和旧历史仍保留警告。详见 [状态表优化](skill-queue-state-optimization.md)。
2. 单曲完整时间线回退仍可能产生较高峰值内存；标准时长排队路径已改为复用状态区间贡献，需要继续观察其他输入及不同设备上的延迟。
3. random-bucket 仍是近似回退，结果必须保留 `quality`/solver 类型可见性。
4. 贡献支配已覆盖固定反例和随机穷举，但仍应扩大 unified、rate-up 和不同冲突图样本。
5. 发布 `scoreRangeChartMeta.2.json` 到实际 CDN/静态服务器并执行线上资源 smoke。
6. 所有真实性能与回归统一使用完整诊断 fixture；Mongo 导出工具必须显式指定输出路径，不再默认写入测试 fixture。
