# 非连锁排队性能回归：1,456 卡新档案

后续已完成[窗口复用优化](skill-queue-window-optimization.md)：关闭详细诊断的同条件原生对照，排队修正版最高分 474.858 → 50.855 秒、平均 PT 467.192 → 64.463 秒，完整业务结果和候选/搜索计数一致。本文保留此前定位回退及复核旧基线的过程，不代表优化后的当前性能。

## 基线复核与口径更正

原先把下面四轮含详细诊断的时间直接作为性能基线，未说明它与历史实验同时存在谱面和诊断开关差异。**59.712 / 293.026 秒不是原活动三曲的正常旧版耗时，+588.8% / +81.3% 也不能作为生产运行的回退倍率。** 原始记录保留，但与后续普通阶段计时分开。

历史实验使用相同冻结输入（1,456 卡、活动 323），三曲为 **186 SP / 395 SP / 772 EX**，均不排队：

- [最高得分共用优化](maximize-shared-optimization.md)：全开两轮核心均值 23.528 秒，墙钟均值 23.656 秒。
- [最高得分四项拆分实验](maximize-four-way-ablation.md)：全开墙钟 36.829 / 31.046 秒，均值 33.938 秒。
- [压缩评分详细计时](compressed-native-timings.md)：平均 PT 两轮核心均值 29.161 秒。

这些历史实验没有开启 `BANGDREAM_OPTIMIZE_DP_TRACE_DETAIL`。本次第一次四轮却开启了该开关；它会在每个候选池评分结束后调用 `global_prune_stats`，重建全局贡献支配上下文并遍历卡牌进行诊断计算。它不是只打印已统计的字段，也不会改变返回的候选。

2026-09-17 补充复核，全部保留普通阶段计时，关闭详细诊断。仍为原生 Release、逐项串行，没有重编译或并发跑基准。以下都是核心时间，各一轮：

| 二进制 / 输入 | 最高得分 | 平均 PT |
|---|---:|---:|
| 本次旧版二进制 / 原 186 SP 三曲 | 34.098 秒 | 42.291 秒 |
| 历史实验原二进制 / 原 186 SP 三曲 | — | 37.259 秒 |
| 本次旧版二进制 / 首曲换成 8 SP | 40.936 秒 | 未补跑 |

历史原二进制 SHA-256 与之前记录的 `b0e483dc452d813e523aa322beeaf864050b876c76ed3c33d9cec767a6ff749f` 完全一致，使用当时相同的实验开关。它当前也没有复现历史 29 秒的速度，因此不能将跨批次墙钟差全部归因于源码回退；当前旧版二进制与历史原二进制之间的小幅差异尚不能由单轮控制确定原因。

原 186 SP 输入复测的完整业务结果与历史记录一致：最高分 10,781,643、原始候选 5,249,105；平均 PT 为 `728394032679 / 1073741824`，原始候选 5,860,064、保留 78,079、二队检查 1,193,604,480、三队检查 19,784,531,363，均与历史一致。生产默认的压缩评分、缓存及四项搜索优化仍开启。

8 SP 最高分在关闭详细诊断后由 59.712 降到 40.936 秒，业务结果、候选数和搜索计数完全一致。候选构建整段为 43.970 → 26.476 秒；其中评分反而为 14.269 → 14.689 秒，剪枝为 6.875 → 7.096 秒。候选池内部总计时扣除剪枝与枚举后的差额由 18.519 降到 0.613 秒，与移除额外全局诊断计算相符；不能把两轮所有时间差精确算作诊断开销。

谱面变化另有真实工作量影响：最高分原始候选由 5,249,105 增至 7,322,414。旧平均 PT 在排队谱面上无法使用独立技能矩阵，回退到完整时间轴的 5 个队长 × 120 个技能顺序评分；原四轮中的平均分转换就用了 221.221 秒。无排队原输入当前复测此阶段仅 1.393 秒。因此 293.026 秒不能与历史原三曲的 29.161 秒直接比较。8 SP 平均 PT 的普通计时尚未补跑，不能从含诊断的总时间直接相减估计。

排队修正版的每候选评分成本明显升高这一定位仍成立，但新旧生产口径的整轮回退倍率需关闭详细诊断后重新测量，不从原四轮推算。此次仅复核记录与测试脚本，没有修改计算算法。

控制材料在 `tmp/skill-queue-benchmark/controls/`，包含原输入最高分 / 平均 PT、8 SP 最高分、历史原二进制平均 PT 的结果、日志、输入及二进制哈希。

## 结果与定位

- 旧最高得分为 10,701,954，修正版为 10,693,326。旧版候选评分独立相加重叠技能窗口，因此旧分数不作为正确性答案；此次对照衡量的是接入正确排队计算的成本。
- 本例最高分两版选择的道具、三队卡牌集合、综合力及队长均相同。第一首 8 SP 从 3,009,956 修正为 3,001,328，另外两首分数相同；总分差异来自该曲排队评分修正。
- 平均 PT：旧版 `721875418517 / 1073741824`，修正版 `721875418517 / 1073741824`。
- 修正版结果中的排队标记为 `single`、`searchMayBeSuboptimal=false`，未走连锁穷举回退。
- 候选数量的变化远小于候选评分耗时变化。最高分采样打点中，第一首排队曲的顺序求解占三曲顺序求解约 96.3%；主要成本在条件窗口和整数增量构造，DP 分配本身只占较小部分。这是采样诊断，不将采样时间直接当作整段时间。
- 当前实现会在每个候选中重复构造多个前驱条件窗口；即使只有第二技能位排队，其余技能位仍参与这部分矩阵构造。下一步优先研究预编译/缓存条件窗口、复用无排队技能位的既有压缩评分，以及减少循环内临时分配。本轮没有改变算法后混入新结果。

## 复现

本地材料位于 `tmp/skill-queue-benchmark/`：`metadata.json`、`source-hashes.json`、`preflight.log`、四组 `*-run.json`/结果 JSON/日志和 `analysis.json`。`run.py` 拒绝覆盖同名已完成轮次，重跑使用新的轮次后缀。脚本已改为默认关闭详细诊断，并将开关和输入哈希写入轮次元数据；只有显式添加 `--detail` 才复现原诊断模式。不同诊断模式不得混算均值。

```powershell
python -X utf8 -u tmp/skill-queue-benchmark/run.py before-max-2 before-pt-2 after-max-2 after-pt-2
python -X utf8 tmp/skill-queue-benchmark/analyze.py
```
