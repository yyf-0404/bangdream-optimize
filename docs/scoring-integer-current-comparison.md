# 当前浮点引擎与旧整数引擎对照

日期：2026-09-21。接续 [候选评分固定参数与初始种子优化](scoring-candidate-operands.md)。本次只复测和记录，没有修改计算逻辑。

## 比较口径

- 旧版：浮点迁移前的 0.4.5，提交 `1685a950bdf5fc88205256d53664ad3f3797af7a`。它已经支持技能延后及加权技能顺序，不能当作更早的 120 种顺序等概率版本。
- 当前版：保留原生 f32 综合力、两段取整和摆放差异处理，已完成候选存储、剪枝上下文复用、Combo 固定参数及初始种子优化。计分规则为 `cn-9.4.4-f32-v1`。
- Windows 原生 Release，固定同一逻辑核（亲和掩码 4）、Above Normal 优先级；每组每版一轮，交替旧版/当前版先后顺序，全部串行。两版都关闭诊断并清除实验环境开关，计时期间没有并行构建或测试。
- 两版使用相同完整输入及本地游戏资源。新档案 1456 卡：活动 323，186 SP / 395 SP / 772 EX；旧档案 1414 卡：原自定义活动，306 EX × 3。最高分强制 `strictExact`，实际结果均为 `solverQuality: exact`；平均 PT 沿用各版正式搜索入口及相同的 1024 路径加权模型。
- 下表时间均为本次直接复测，未拼接之前开启诊断或不同轮次的记录。墙钟包含进程启动、资源读取、计算和结果落盘；阶段耗时来自引擎 metrics。不是 WASM 或浏览器性能测试。

当前原始候选仍比旧整数版多约 6.8%–11.7%，但候选构建耗时的差距已较小，旧档案平均 PT 还更快。这与保留浮点边界所需的候选范围及减少重复准备工作的优化同时存在，并不意味着改回整数剪枝。

两组最高分的 `exactWork` 分别为 6,208,026,993 → 6,211,291,216、1,504,872,782 → 1,505,799,967，只增加约 0.05% / 0.06%。平均 PT 新档案的第二队检查为 1,193,604,480 → 1,196,068,789，第三队为 19,784,531,363 → 19,760,261,009；旧档案分别为 556,255,667 → 578,250,973、4,769,185,533 → 4,858,343,447。因此不能把本轮三队阶段的全部时间变化解释为检查次数减少或增加。

新档案最高分剩余差距主要落在候选构建；旧档案最高分的候选构建、道具上界准备和求解都有增加。若继续优化，仍应分别测量这几部分，不能只根据总时间决定删减浮点评分或正确性保护。

## 结果核对

8 份输出分别与对应版本保存的完整业务输出及全部非计时 metrics 一致。业务比较排除 `metrics`、`solver`，工作计数单独比较时仅排除以 `Ms` 结尾的计时字段。当前输出也与上一轮开启诊断时一致。

新旧算术之间结果本来就有差异，本次没有要求二者相等：

| 档案 | 最高分：旧 → 当前 | 平均 PT：旧 → 当前 |
| --- | ---: | ---: |
| 1456 | 10,781,643 → 10,781,591 | 678.369805849 → 678.378617025 |
| 1414 | 11,815,764 → 11,815,694 | 735.074854617 → 735.074846692 |

两组最高分选出的各曲成员集合和道具相同；上表差异是此前计分算术迁移已有的结果，本轮性能优化没有新增结果变化。平均 PT 为精确分数换算后的展示小数，原始分子/分母完整保留。
