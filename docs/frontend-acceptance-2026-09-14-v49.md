# v49 入口调整与视觉复查

日期：2026-09-14。预览：`http://127.0.0.1:8093/?design=49#archive`。

本轮逐页打开实际页面和主要弹窗、查看截图，再结合 DOM 尺寸核对裁切与溢出。下列范围是本轮实际检查，不把既往计算测试、DOM 文本存在或编译通过等同于原生桌面视觉通过。没有提交 Git。

## 入口调整

- 顶部档案切换旁新增“导入”，加载档案后可用。从任意页面导入到正在使用的档案，不会跟随档案目录中临时查看的另一档案改变目标。
- 档案页原导入入口仍作用于目录中选中的档案。使用不同的当前／查看档案实测了两个入口的目标，再取消导入。
- 浏览器“下载桌面端”移到侧栏“问题反馈”上方，下载弹窗移出资源管理面板，在其他页面也可打开；手机侧栏折叠后仍有入口。
- 下载目录为空或读取失败时显示重试。桌面运行时隐藏此入口，并在动作处理函数中阻止误开。

## 本轮发现并修复

1. 新增下载入口后，960×640 矮窗口中侧栏底部操作被挤出。降低矮窗口品牌区、导航和底部的垂直间距，长状态提示下计算按钮仍完整可见；复查侧栏滚动高度与可见高度相同。
2. 结果页“歌曲详情”继承了不合适的重置样式。补齐统一标题栏、关闭按钮、内容留白和封面／文字布局，宽屏并排、窄屏上下排列，保留共用 D 难度标识。已查看两种尺寸的修复后截图。
3. 歌曲选择器顶部难度按钮被按钮重置覆盖，窄屏封面容器又被通用 span 宽度撑开。恢复空心／实心难度按钮和固定封面尺寸，已查看 960×640 与 390×844 修复后截图。
4. 单队模式仍显示“三队不能重复角色”的说明。改为按模式显示单队或三队规则。
5. 结果页“更多结果操作”列表被头图的 overflow 裁切。裁切范围收回到图像层，菜单可越过头图底边，并补齐行高与悬停反馈；1280×900 和 390×844 截图复查完整显示五项操作，窄屏计算诊断空状态也正常。
6. 新档案导出界面直接使用浏览器下载，绕过桌面保存接口。改为调用共享运行时的 `saveJsonFile`，桌面进入原生保存窗口；取消不当作成功，失败可重试。两种导出内容均为 JSON，保存扩展名统一为 `.json`。原生窗口标题改为通用“保存文件”。
7. 档案概览中的国服卡缩略图请求失败后，只剩“最近持有的卡牌”标题。新增完整原画回退；全部候选失败时收起空样例区域，持有统计保持不变。实际五张均成功回退到国服原画（自然宽度 1334），已查看最终截图。

## 桌面端差异及验收边界

| 差异 | 当前实现和本轮证据 | 尚未验证 |
| --- | --- | --- |
| 下载桌面端 | 仅浏览器显示；桌面隐藏及阻止动作调用已有自动测试 | 本地 `/downloads/` 返回 404，已检查失败／重试；没有成功下载或安装安装包 |
| 文件保存 | 档案与诊断共用运行时保存；桌面调用 `save_json_file`；模拟 Tauri invoke 验证成功、取消、写入失败 | 未打开真实 Windows 保存对话框，也未做真实文件保存截图 |
| 资源管理 | 依据运行时能力显示核心资源刷新、全量资源同步；桌面隐藏浏览器专用本地清理操作，已测试可见性分支 | 没有执行全量同步或清理缓存，以免改动当前数据 |
| 计算与档案存储 | 桌面通过 Tauri／Rust、本地档案接口，浏览器使用浏览器运行时；界面组件及样式保持共用，运行方式差异不能成为布局退化的理由 | 本轮桌面编译通过，没有重新执行原生计算、重启持久化或多窗口场景 |
| 素材通道 | 桌面通过 `load_header_asset` 读取二进制并交给共用纹理流程；浏览器通过开发服务代理，实际 #339 为 ready | 没有原生 WebView2 中的纹理截图或 Windows 缩放比例检查 |
| 反馈 | 桌面需要配置反馈服务地址，不能假设浏览器的同源服务存在；共用反馈布局已在浏览器查看 | 未提交反馈或验证真实邮件服务 |

首次检查时只能控制浏览器。随后继续验收时，原生工具可用，已启动本次构建的 Windows 客户端并找到实际窗口；两次截图均报 `SetIsBorderRequired: 不支持此接口 (0x80004002)`。转为读取控件前，用户按 Esc 停止操作，之后同意结束验收。本次未修改桌面档案，也未完成真实保存／取消操作。

不能宣称“桌面端全量视觉验收通过”；WebView2 字体／系统缩放、窗口缩放、原生文件对话框及本地运行行为仍未实机验收。
