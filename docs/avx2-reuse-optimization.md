# AVX2 候选前缀复用优化（2026-09-16）

在平均 PT 的近优带扫描中，将第二队冲突检测改为 AVX2 批量过滤，并复用固定第一队下可兼容的第三队分数前缀。没有构建卡牌倒排位图，也没有使用上一版兼容上界 / 共同卡预判。

已设为原生 AVX2 的默认近优带扫描路径。新档案本轮扫描耗时减少 82.9%、完整计算减少 62.8%；旧档案扫描减少 40.1%，但整次运行耗时基本持平。

## 同轮完整档案对照

原生 Release，Ryzen 5 5500U，单线程搜索。每个档案两种模式使用同一个可执行文件，通过实验环境变量切换。每种模式各跑一次，没有额外预热；执行顺序为新档案基线 → 复用，再旧档案复用 → 基线。准备和索引成本包含在扫描耗时内。

|---|---:|---:|---:|
| 1456 卡：完整计算 | 280.419 s | 104.368 s | 62.8% |
| 1456 卡：三队扫描 | 215.885 s | 36.915 s | 82.9% |
| 1456 卡：候选生成 | 59.538 s | 63.416 s | -6.5% |

## 算法与正确性

1. 按原顺序准备三个歌曲候选列表。第二队的掩码按字分列，一次用 AVX2 检查四个候选，按原顺序收集兼容位置。
2. 固定第一队，等遇到首个兼容第二队时，只筛选当前分数下界允许的第三队前缀。移除与第一队冲突的候选，并紧凑保存剩余位置和掩码。
3. 后续第二队的分数不升、动态下界不降，因此所需第三队前缀只会缩短，先前筛出的列表可以安全复用。第三层用 AVX2 检查第二队与该列表的冲突。
4. 缓存原列表的分数边界，只有边界确实缩短时才重新查找；避免上一版对数亿个被剪枝分支分别二分计数。
5. 保留原候选位置，用位置差累计被过滤的逻辑检查次数。回调抬高下界、立即停止和边界相等时，结果访问次序及计数均保持一致。

固定 1～4 个掩码字数也让编译器能够展开短循环，避免宽掩码内层每批再按动态字数迭代。该贡献没有与列表复用单独拆分计时。

新增存储为候选数与掩码字数的线性量级，只保存当前第一队的复用列表，不分配 N×N 兼容关系矩阵。1～4 个 u64 使用专门化内核，更宽掩码回退到现有 AVX2 扫描。

## 边界性能控制

这些是合成控制案例，每种模式交错测量四次。回调只记录访问，不包含真实 PT 分布计算，不能把这些数字当成完整选队性能。

| 场景 | AVX2 基线中位数 | 前缀复用中位数 |
|---|---:|---:|
| dense-small | 44.645 ms | 44.462 ms |
| dense-early-stop | 0.489 ms | 0.931 ms |
| all-conflict | 111.512 ms | 12.859 ms |
| mixed-dynamic | 0.668 ms | 0.789 ms |

大量兼容的小样本耗时范围重叠；首个结果立即停止时，预先准备列表会增加约亚毫秒级成本。因此此优化并非对所有输入都保证更快。

## 默认行为与对照开关

正常构建不需要实验特性即可使用前缀复用；不具备 AVX2 的平台仍使用原标量路径，超过四个掩码字则使用原宽 AVX2。最高分种子搜索、候选生成、18,500 近优带规则和技能概率模型均未调整。

要在研究构建中选择旧实现，启用 `experimental-avx2-second-prune`，并设置 `BANGDREAM_OPTIMIZE_BAND_BACKEND=scan`：`BANGDREAM_OPTIMIZE_AVX2_SECOND_PRUNE=off` 使用整批冲突跳过的旧 AVX2；`bound` / `common` 保留前一轮实验；`reuse` 或未设置该变量使用前缀复用。

- 默认构建和开启实验特性的构建各通过 22 项 solver 单元测试，各忽略 2 项性能探针。覆盖 1 / 2 / 3 / 4 个字及更宽回退、边界相等、动态下界、立即停止、空掩码、相同分数、原始候选编号和饱和加法。
- 四轮完整档案结果的全部非计时字段与此前 AVX2 结果一致，包括精确 PT 分子分母、卡牌、队长、推荐顺序、候选数、配对及第三队逻辑检查次数。
- 新档案：1,456 卡，国服活动 323，186 SP / 395 SP / 772 EX；旧档案：1,414 卡 fixture，自定义活动、306 EX × 3。两者都使用当前加权技能概率模型。
- 研究代码与数据在 `tmp/avx2-reuse-study/`，完整计算程序在 `tmp/profile323-research/`。输入、程序哈希及时间记录在各 `*-run.json` 中，旧可执行文件和每轮结果均保留。
- 核心库默认构建检查和 WASM 编译检查通过；WASM 保留四项原有未使用导入、变量或函数警告。本轮性能数据仅覆盖原生 AVX2。WASM 和非 x86 平台不使用这套 AVX2 优化。
