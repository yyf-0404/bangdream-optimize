# 浮点评分迁移后的控分基准

日期：2026-09-21。接续 [候选存储与摆放分组优化](scoring-candidate-storage.md)。本轮补测完整档案的控分性能及结果，不修改计算实现。

后续的 [浮点缓存审计](scoring-cache-audit.md) 同时覆盖组队和其他活动的控分，记录命中率、逐项关闭对照及撤回的查询结构试验。

## 条件

- 使用此前对照的两份完整档案：新档案 1456 张卡、旧档案 1414 张卡，保留实际养成等级、角色及道具数据。
- 使用真实的国服活动 320（对邦）。活动 323 是巡回活动，不适合作为控分入口基准；本次没有沿用它。
- 本地谱面元数据共 3394 份，歌曲资料 809 条。按正式入口的服务器及发布时间规则处理后，搜索入口记录 3070 份谱面；之后仍按技能时长、风险和上下界等规则筛选。不是只对活动曲控分。
- 固定 `nowMillis=1790035200000`，即 2026-09-22 00:00:00 UTC，保证各轮发布时间筛选一致。
- 从 0 精确补齐到 10,000 PT，分别测试 Auto 50% 和 75%。`maxResults=1`，与当前前端一致。
- 三个原生 Release 版本，固定同一逻辑核（掩码 4）及相同进程优先级，交替顺序串行执行。每场景每版本先预热一轮，再正式测三轮；共 48 次成功运行。正式计时期间没有并行构建或其他测试。

旧整数版为提交 `1685a950bdf5fc88205256d53664ad3f3797af7a`（0.4.5）；“优化前”已经完成 f32 迁移及安全剪枝收紧；“当前”增加了上一轮候选存储和摆放分组优化。

测试输入补齐了本地完整卡牌资料中的等级综合力表。最初直接复用的紧凑测试资料缺少旧档案某些未满级卡的等级参数，例如卡牌 2311 的 40 级，因此被数据校验拒绝。补齐时不修改档案等级，也不把与计算无关的完整卡牌描述塞入输入。失败的初始试跑及完整描述造成的输入膨胀试跑均不计入下表。

## 成本变化

上一轮改动的 `RawTeamCandidate` 存储及 `TeamPowerGroups` 主要服务编队评分。控分走独立的二卡/三卡 MITM、分数区间反求和队伍恢复路径，因此本轮没有观察到直接加速。

诊断日志将主要新增成本归入道具及队伍检索阶段，其中包含浮点综合力区间反求、扩大的安全检索范围和实际队伍恢复校验：

| 档案 / Auto | 道具及队伍检索累计：旧整数 → 当前 | 模式准备累计：旧整数 → 当前 |
| --- | ---: | ---: |
| 1456 / 50% | 0.518 → 1.785 s | 0.029 → 0.167 s |
| 1456 / 75% | 0.557 → 2.186 s | 0.030 → 0.160 s |
| 1414 / 50% | 0.368 → 1.421 s | 0.029 → 0.155 s |
| 1414 / 75% | 0.341 → 1.312 s | 0.029 → 0.153 s |

这些来自各目标层的计时累计，不是函数级采样剖析，尚不能把整个差额归到其中某个函数。

四组的道具批次数、基础及增量查询次数、整桶剪枝次数、最大二卡索引规模，旧整数版与当前均相同。前三组的分数边界缓存数量也相同；旧档案 75% 的 PT 区间段数由 5655 变为 5656。优化前后全部批量搜索计数一致。证据更支持“同类查询在精确浮点路径下更贵”，没有观察到候选规模爆炸。后续应优先细分和优化浮点边界批量反求、模式准备及队伍恢复，保留最终原生算术校验。

## 正确性

- 48 次均返回非空方案；按 `pt × count` 累计严格等于 10,000，队伍均有五张不同卡，次数统计一致。
- 两份档案 Auto 50% 均为 4 次、9 火；75% 均为 3 次、7 火。三个版本的这些目标值相同。
- 同版本重复运行的全部输出一致；浮点优化前后，队伍摆放顺序、道具、歌曲、分数、PT 及其他字段完全一致。旧整数版选出的具体队伍不同，不能要求错误算术模型与新模型逐字段一致。
- 实际 WASM 模块通过 Node 调用，四组结果与原生逐字段一致。
- 对当前四份方案涉及的八个“场景 × 曲目”组合，加载原始完整谱面，按返回的五人摆放顺序、第三位队长、选中道具和对应 Auto 倍率，另走指定队伍结算入口。显示综合力一致，每个可达技能顺序的分数均等于控分返回值，并落在对应 PT 的合法分数区间内。
- 本轮没有重新穷举全部可能队伍或全部浮点边界；以上是完整档案搜索、跨目标端一致性和实际返回方案的独立入口复核，不是新增的全空间最优性证明。

WASM 一致性运行不是与上表相同的预热基准：同一 Node 进程首次计算观察到约 27.0 秒，后续三场景约 5.30、3.78、4.11 秒，包含序列化及模块调用。没有单独测定首次调用成本的构成，也没有测浏览器 UI 或 Worker 端到端延迟，因此不把原生 2.6–3.5 秒表述为网页耗时。
